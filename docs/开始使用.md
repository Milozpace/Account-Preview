# 开始使用

本页供 Agent 执行首次配置。使用者的准备和交互见[新手配置指南](新手配置指南.md)，简短检查顺序见[Agent 启动说明](Agent启动说明.md)。

目标是在本人电脑完成“环境与 App 就绪 → 一个选定月份的账单入账 → App 查看”。当前桌面支持 Windows x64、macOS Apple Silicon。预算和 Android/坚果云是可选项。记账 Skill 随项目提供，Agent 读取项目文件即可按它执行。Agent 与模型服务由使用者自行选择。

## 1. 先确定项目根与现有状态

本人选择一个长期保留的普通目录，记为 `ROOT`。核对其完整绝对路径、系统架构和现有文件，读取 `AGENTS.md`。实际账本放在本人选定的使用目录，保留已有数据与配置。

| 已有状态 | 本次分流 |
| --- | --- |
| 全新目录，无来源配置和 SQLite | 取得同版源码、准备环境后再预检 init |
| 已有 `data/source.json` 或 SQLite | 先 doctor/verify，按原账本续接 |
| 有库无来源、来源无库、来源无效 | 保留现场，查初始化或恢复证据 |
| 只缺个人档案或 PROJECT_MEMORY | 核对实际库后补状态指针 |
| 已有 App 或其他桌面绑定 | 核对安装身份与原绑定，使用下文的冲突处理 |

新项目默认 preview 身份，即 `com.account.preview` / `AccountPreview`。已有 personal 继续原 `com.account.probe` / `AccountDesktop`，个人交付按[更新与恢复](更新与恢复.md)。

## 2. 取得同一发布版源码与组件

先读默认分支的最新配置入口，再从[发布页](https://github.com/Milozpace/Account-Preview/releases)选择实际已发布版本。下载该 Release 的 `-source.zip` 与本机平台 ZIP，并核对 `SHA256SUMS`。也可由干净 checkout 取得对应 tag 源码，保留已有修改。

后续命令使用选定版本的代码和同版文档。开发分支可能已有未交付能力，按发布索引中的提交、身份、平台与哈希确认实际组合。公开下载可匿名进行。

在源码根执行启动器预检，核对输出 `root`、`source` 和 `steps`。Git 来源指向本仓库，发行源码来自所选发布版。来源检查和包哈希校验均需保留。

以下命令是模板。Agent 替换 ROOT 等占位为已核对的绝对路径，按当前 shell 引用含空格路径。除另有说明，工作目录为 ROOT。

Windows 先预检，再按已授予的配置授权执行。

```text
.\bootstrap.ps1 --expected-root ROOT --repo Milozpace/Account-Preview --configure-desktop --install-app
.\bootstrap.ps1 --apply --expected-root ROOT --repo Milozpace/Account-Preview --configure-desktop --install-app
```

macOS Apple Silicon 使用同一组参数。

```text
sh ./bootstrap.sh --expected-root ROOT --repo Milozpace/Account-Preview --configure-desktop --install-app
sh ./bootstrap.sh --apply --expected-root ROOT --repo Milozpace/Account-Preview --configure-desktop --install-app
```

启动器根据本份源码选择对应 tag，准备固定 Python 3.12.12、项目 `.venv` 和锁定依赖，校验组件、安装并绑定 App。实际执行需要 `--apply --expected-root ROOT`。仅准备环境时省略组件、安装和绑定选项。

已有可用 gh 时可复用，缺少或未登录时启动器回退公开下载。网络受限时，先核对手动下载的同版源码、桌面 ZIP 与 SHA256SUMS，再用 `--bundle 桌面ZIP绝对路径` 替换 `--repo ...`。启动器继续验证包内清单和组件哈希。

PowerShell 阻止脚本时，仅调整本次进程的启动方式并保留真实退出码。缺产物、架构不符或下载失败时，根据具体错误续接。普通使用运行预构建包。

## 3. 检查环境、组件与绑定

后文 `PY` 为 ROOT 的项目 Python，Windows 为 `ROOT/.venv/Scripts/python.exe`，macOS 为 `ROOT/.venv/bin/python`。

```text
PY scripts/account.py --root ROOT doctor
```

| 输出或现象 | 如何判断 |
| --- | --- |
| `setup.state=uninitialized` | 结合实际来源/库检查，确认为新项目才 init |
| `setup.state=initialized` | 核对账本状态后续接 |
| `setup.state=incomplete/invalid` | 保留现存文件，定位异常 |
| `desktop.profilePresent=true` | 仅证明配置文件存在，还要核对其指向 |
| `desktop.installation=unverified` | 需要另行确认实际安装与 App 打开 |
| `cloud.state=unverified` | doctor 没有验证云端，结合实际配置解释 |
| steps 的 `planned/completed/unchanged/skipped` | 分别表示计划、已执行、相同配置、未选步骤 |

doctor 的顶层 ok 也包含未初始化场景，须读各项状态。安装完成、绑定正确和实际页面可用分别确认。

桌面配置指向本项目和项目 Python，helpers 由 `.runtime/helpers.json` 选择。

| 系统 | preview 绑定配置 |
| --- | --- |
| Windows | `%LOCALAPPDATA%/AccountPreview/project.json` |
| macOS | `~/Library/Application Support/AccountPreview/project.json` |

已有项目还要核对双发布门禁及本次授权。doctor 不读取凭据或证明发布已关闭，import/refresh 可能沿已有门禁自动发布。核对方法见随版[记账 Skill](../.agents/skills/account-maintenance/SKILL.md)。

## 4. 确认为新项目后建立观察账本

先确定起始月份及本批文件范围，通常选择最近一个完整月。起始月不晚于首批最早交易月。

```text
PY scripts/account.py --root ROOT init --effective YYYY-MM
PY scripts/account.py --root ROOT init --effective YYYY-MM --apply
PY scripts/account.py --root ROOT verify
PY scripts/account.py --root ROOT refresh --apply
```

默认省略 amounts 和 initial，得到四池零额度、零初始滚存及新库观察模式。观察期显示“未设预算”，实际分类和分池消费照常可见。预算启用、历史额度和旧账本的兼容边界统一见[四池预算设置](四池预算设置.md)。

init 重试会检查现有库及参数。遇到 incomplete/invalid 状态先核对原参数和恢复记录。已有账本按其现有状态使用。

初始化会创建本机状态文件。Agent 按实际情况补充 `local/档案.md`，保留所有者原有文字，记录起始月、预算未制定、零滚存及手机同步是否启用。批准规则单独写 `local/个人规则.md`，日常执行仍指向随版 Skill。

## 5. 首批记账与查看

本人选择本地 CSV/XLSX 并授权后，读取[记账 Skill](../.agents/skills/account-maintenance/SKILL.md)。原件归档、prepare、审核、事务写入、verify、幂等及后处理均按该入口执行。未提供账单时报告环境/空库就绪，等待本人文件。

按用途证据完成主分类和分池。实际用途不明的小额消费可留待定并说明原因，影响事件、净额或关联的疑问先澄清。预算是否制定按实际状态汇报。

打开对应身份的电脑 App，核对导入月的收支、分类、日历及明细。记录真实文件覆盖范围，缺失平台或期间留作说明。显示异常先查本人根、绑定和本地快照。

## 6. 完成本地体验，再按需扩展

向使用者说明环境、安装/绑定、首批入账、分类/池待定项、实际 App 显示和预算状态。根据事实标记已完成、失败或未执行。

查看后按[规则与学习](规则与学习.md)做两三个简短访谈。正式额度走[四池预算设置](四池预算设置.md)，手机查看与上传走[手机与同步](手机与同步.md)，导出和备份见[工作说明](工作说明.md#导出备份与恢复候选)。

## 绑定冲突和配置续接

同一系统用户、同一安装身份只有一个桌面绑定。默认拒绝覆盖另一根。若本人明确迁移/切换自己的项目，关闭 App、停止其他配置写入，再指定已核对的旧根。

```text
.\bootstrap.ps1 --apply --expected-root ROOT --configure-desktop --rebind-from OLDROOT
sh ./bootstrap.sh --apply --expected-root ROOT --configure-desktop --rebind-from OLDROOT
```

按系统选择一条。工具核对旧根，在配置旁保存 `project.json.backup-*` 并返回 `desktop.backup`。该操作只切换绑定，账本迁移另按实际授权处理。锁协调 bootstrap，执行时保持 App 和其他配置写入器关闭。

重跑 bootstrap 会重新核验 Python、同步依赖和校验组件。相同绑定返回 unchanged，显式 `--install-app` 会再次运行安装。保留已完成的环境，按失败环节重试。

## 安装身份与系统提示

| 项目 | personal | preview |
| --- | --- | --- |
| 应用名 | Account | Account Preview |
| 标识 | `com.account.probe` | `com.account.preview` |
| Windows 默认安装目录 | `%LOCALAPPDATA%/Account/` | `%LOCALAPPDATA%/Account Preview/` |
| Windows 绑定 | `%LOCALAPPDATA%/AccountDesktop/project.json` | `%LOCALAPPDATA%/AccountPreview/project.json` |
| Windows 原生安全存储 | `%APPDATA%/com.account.probe/` | `%APPDATA%/com.account.preview/` |
| macOS | 当前无 personal 交付 | `~/Applications/Account Preview.app`，用户可自选位置 |

安装位置以实际安装信息为准。macOS preview 的原生存储在 `~/Library/Application Support/com.account.preview/`。凭据、Keychain 和配对分别由对应安装身份保护。

Windows 当前包的系统提示与发布方签名情况有关，先核对来源和校验结果再由本人处理。macOS 当前为 ad-hoc 签名、未经 Apple 公证，按[Apple 官方说明](https://support.apple.com/en-us/102445)处理首次打开。详细边界见[架构与部署边界](架构与部署边界.md#签名与安装身份)。

本地文件和所选云端 Agent 的隐私范围见[同步与隐私](同步与隐私.md)。
