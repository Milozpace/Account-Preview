# 开始使用：先完成电脑本地 mini 体验

准备 Windows 或 macOS 电脑，以及能读取本地文件、执行命令的 Agent。先体验“给出一个月账单 → Agent 审核记账 → 电脑 App 查看”，不要求手机、坚果云账号或配对，也不要求先想好预算和完整分类体系。Account 不提供 Agent 或模型 API，普通使用无需 Rust、Node 或 Android SDK。

## 1. 取得仓库权限，选择长期目录

私有仓库须已有本人本机认证；没有权限时由 Agent 说明具体登录步骤，不在聊天中索取令牌、密码。可以常规 clone 或下载源码包，首次配置以仓库默认分支的最新说明为准。

选择长期保留的普通目录，记录绝对根路径并读取 `AGENTS.md`。正式账本不放在临时 Git worktree、`worktrees` 或 `archive` 目录，不指向作者或其他人的账本。预览应用标识为 `com.account.preview`，与生产 App 配置和身份隔离。

## 2. 准备环境和电脑版

启动器默认预检；获准本机配置后加 `--apply`，自动准备固定 Python 3.12.12、项目 `.venv` 与哈希锁定依赖。下载私有 Release 要求 `gh` 已登录有权限的本人账号。

从仓库根按系统选一条，可一次取得电脑包、安装并绑定：

```text
.\bootstrap.ps1 --apply --repo Milozpace/Account-Preview --tag v0.4.0-preview.1 --configure-desktop --install-app
sh ./bootstrap.sh --apply --repo Milozpace/Account-Preview --tag v0.4.0-preview.1 --configure-desktop --install-app
```

也可先下载对应 ZIP，用 `--bundle ZIP路径` 替代 `--repo ... --tag ...`。只准备环境时使用启动器加 `--apply`；详细参数见 `bootstrap.py --help`。Windows 执行策略阻止脚本时，Agent 可使用仅针对当前进程的启动方式，不改全机策略。缺权限、产物或架构不匹配时说明实际下一步，不用作者机器的旧工具替代。

桌面绑定由 `--configure-desktop` 写入：

| 系统 | 预览配置位置 |
|---|---|
| Windows | `%LOCALAPPDATA%/AccountPreview/project.json` |
| macOS | `~/Library/Application Support/AccountPreview/project.json` |

它指向本项目和本项目 `.venv`；匹配 helpers 由 `.runtime/helpers.json` 指向版本目录。此时不使用 `--initialize-identity` 或 `--enable-publish`，不需要云端凭据。

macOS 内部包使用 ad-hoc 签名，未经 Apple 公证，见 [Tauri 说明](https://v2.tauri.app/distribute/sign/macos/)。首次阻止时由本人按 [Apple 步骤](https://support.apple.com/en-us/102445)，在“系统设置 → 隐私与安全性”为 Account Preview 选择“仍要打开”，不关闭全局防护。来源不明、损坏或恶意软件提示时保留现场检查。

下文 `PY` 为项目 Python：Windows `.venv\Scripts\python.exe`，macOS `.venv/bin/python`；`ROOT` 为本项目绝对目录，由 Agent 替换并引用含空格路径。

```text
PY scripts/account.py --root ROOT doctor
```

核对本机路径、Python、SQLite、依赖、组件与桌面绑定。`cloud.state=unverified` 是当前工具的原始状态；未选同步时解释为“可选同步未启用”，不因此判定本地失败，也不声称云端已验证。

以上默认流程针对首次配置。续接已有项目时，先核对实际身份和两道发布门禁：已有同步配置不重置，也不能仅凭 `cloud.state=unverified` 就断言同步未启用。导入或刷新前说明现有门禁是否可能自动发布；仅获本地操作授权而发现发布已开启时，先处理授权范围，不直接执行会上传的步骤。

## 3. 选择一个月，建立观察阶段空库

先问“你想整理哪个月，有哪些本地账单文件？”推荐最近一个完整月，即上月。本版 App V2 当前展示本月与上月，较早记录可入库供 Agent 分析，但不能承诺会出现在当前 App 页面；不能为展示改交易日期或系统日期。记录实际平台与期间覆盖，不把部分文件说成整月全部支出。

首次只需解释“先看支出，再决定是否做预算”。不用要求用户给四个额度，也不用预先做完整访谈。**当前程序仍要求四池数值才能建库，mini 使用全零技术占位；这不代表用户希望每月只能花 0 元。** 这是本版文档约定，未新增“无预算”按钮或命令。

Agent 将[现有全零模板](../templates/预算额度.json)复制到本机 `local/预算占位.json`，初始滚存默认全零。仅对全新账本使用；已有账本、已确认预算、规则和身份均保留，不能重置为零。

```text
PY scripts/account.py --root ROOT init --effective YYYY-MM --amounts local/预算占位.json
PY scripts/account.py --root ROOT init --effective YYYY-MM --amounts local/预算占位.json --apply
PY scripts/account.py --root ROOT verify
PY scripts/account.py --root ROOT refresh --apply
```

`YYYY-MM` 使用确认的记账起始月，不晚于首批最早交易月份。先预检，已有本地建库授权时继续执行。重复初始化不覆盖已有账本。

初始化后，Agent 合并补充本机 `local/档案.md`，保留原有内容：

- 使用阶段：mini 本地观察。
- 预算状态：未制定；库内四池零值仅为建库兼容占位。
- 初始滚存：零；没有历史结转承接。
- 分类/分池：按证据做简单主分类，不强制四池；未定资金池保留待归类。
- 手机与同步：未启用（可选）。

程序生成的档案仍可能只有基础字段，以上状态需由 Agent 补入；不是已经实现的数据库或 UI 功能。预算区仍可能显示 0、待归类、进度或超支信息，未制定预算时暂不据此评价消费。不能为了让提示好看而虚构大额度、把个人消费改为非消费或强行分池。占位只用于预算参数，真实交易金额缺失仍不得补零。

## 4. 首批记账并在电脑查看

由本人选择一个月的本地 CSV/XLSX 文件并授权本批记账，保留原件。这里是让本机 Agent 读取本地文件，不要求先用手机上传。按[工作说明](工作说明.md)完成 prepare、审核、import 预检、显式写入和核验，再生成本机快照。

首批优先判断本人真实承担的净额、转账、退款和报销关系。影响净额或归属的重要疑点先询问；用途、主分类或资金池未定时保留真实的不确定状态，不为了“全部完成”猜测。能确认个人消费但资金池未定的，保留实际消费金额与简单分类，资金池可为“待归类”。

Agent 给出本批新增/重复/待确认数、净消费、主要分类和典型样本，引导打开电脑 App 核对。预算未制定时重点看交易、净额和分类，不用四池余额、超支或安全积累评价这个月。App 的待归类提示可能还包含未分池记录，应解释具体含义。

## 5. 看完以后，做一次简短访谈

按[规则与学习](规则与学习.md)先问两三个问题，例如：“哪块支出最出乎你的意料，接下来想留意？”“这些分类有没有不符合你习惯的？”允许回答“不确定，先记着”。

第一轮只整理关注点和少量分类修正，不要求立刻给预算、不预设消费约束、不把关注意向自动升级为长期规则。需要保存规则、修改历史或增加正式预算时，再确认范围和依据。mini 阶段不承诺适合所有人的完整分类或支出管理。

## 6. 本地完成；扩展以后选择

完成标准：项目环境和桌面绑定正确，独立账本核验通过，本人选择的首批账单已按授权处理，电脑能查看有效结果，访谈结论或“暂不决定”已记录。若暂未提供账单，可报告“本地环境与空库就绪，等本人选择文件”，不能虚报首批入账。

交付时分开报告：“本地可用 / 预算未制定 / 手机与同步未启用（可选）”；后两项不阻塞基础体验。本人希望手机查看或投递账单时，再按[手机与同步](手机与同步.md)建立同步身份、安装 Android、配置坚果云、配对和授权发布。启用时沿用现有账本，不重做此前步骤。

隐私小注：账单、账本与个人规则默认保存在本机，不提交共享仓库。本人授权的 Agent 如调用云端模型，读到的内容可能按其设置发送给模型服务；可选手机上传还会经坚果云加密中转，详见[同步与隐私](同步与隐私.md)。
