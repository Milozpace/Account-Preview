# 开始使用：先完成电脑本地 mini 体验

准备 Windows 或 macOS 电脑，以及能读取本地文件、执行命令的 Agent。先体验“给出一个月账单 → Agent 审核记账 → 电脑 App 查看”，不要求手机、坚果云账号或配对，也不要求先想好预算和完整分类体系。Account 不提供 Agent 或模型 API，普通使用无需 Rust、Node 或 Android SDK。

## 1. 取得仓库权限，选择长期目录

仓库现已公开，可以直接用 HTTPS clone 或下载源码包，不需要邀请、GitHub 账号或登录。首次配置以仓库默认分支的最新说明为准；只有提交代码、管理发布等写操作才需要维护者权限，不在聊天中索取令牌或密码。

选择长期保留的普通目录，记录绝对根路径并读取 `AGENTS.md`。正式账本不放在临时 Git worktree、`worktrees` 或 `archive` 目录，不指向作者或其他人的账本。预览应用标识为 `com.account.preview`，与生产 App 配置和身份隔离。

Agent 必须核对这就是本人选定的那份 clone/解压目录，不能按相似文件夹名推断。先运行该目录的 bootstrap 预检，核对输出 `root`、`source`；Git 来源须指向 `Milozpace/Account-Preview`，源码包须来自所选发布版并核验校验值。后文 `ROOT` 一律替换为这个完整绝对路径。执行 bootstrap `--apply` 时必须同时传 `--expected-root ROOT`，目标不匹配会在配置前停止；PS/sh 在下载运行环境前检查。路径已经选定且配置已获授权时连续执行，无需逐条重复确认；换目录或存在歧义时先澄清。来源检查用于防止误选目录，不替代可信发布来源与哈希校验。

## 2. 准备环境和电脑版

先核对[发布页](https://github.com/Milozpace/Account-Preview/releases)选择实际已发布的版本，使用该标签的完整源码和包，不以 main 或文档中的例子作为最新版本。2026-11-01 本轮的已发布基线为 `v0.4.0-preview.1`，`0.4.1-preview.1` 当时尚为候选；以后以实际发布记录为准。Agent 应先保存入门指引，再在干净 checkout 切到所选标签或解压该版源码 ZIP；已有个人修改的目录不得强制 checkout/reset。源码与原生组件版本不同会被新启动器拒绝。未发布候选只供开发验证。

启动器默认预检；获准本机配置后加 `--apply --expected-root ROOT`，自动准备固定 Python 3.12.12、项目 `.venv` 与哈希锁定依赖。公开 Release 可匿名下载，不要求安装或登录 `gh`。

从仓库根按系统选一条，可一次取得电脑包、安装并绑定：

```text
.\bootstrap.ps1 --apply --expected-root ROOT --repo Milozpace/Account-Preview --configure-desktop --install-app
sh ./bootstrap.sh --apply --expected-root ROOT --repo Milozpace/Account-Preview --configure-desktop --install-app
```

启动器默认取得本份已发布源码对应的 tag，不自动跟随 main。已有可用 `gh` 时可复用；未安装或未登录时自动尝试公开下载。若网络受限，浏览器打开发布页，下载同版源码 ZIP、本机架构的桌面 ZIP 和 `SHA256SUMS`，先将两个 ZIP 的 SHA-256 与该校验文件对应条目逐一比对，再解压源码，用 `--bundle ZIP路径` 替代 `--repo ...`。启动器还会校验包内清单及组件字节。不要取开发者 evidence 目录、历史缓存或不匹配的旧包。仓库以后若改回受限，浏览器也须登录有权限的账号，或本人在终端 `gh auth login`；当前公开流程无需此步。

只准备环境时使用启动器加 `--apply --expected-root ROOT`；详细参数见 `bootstrap.py --help`。Windows 执行策略阻止脚本时，Agent 可使用仅针对当前进程的启动方式，不改全机策略。缺产物或架构不匹配时说明实际下一步，不用作者机器的旧工具替代。

桌面绑定由 `--configure-desktop` 写入：

| 系统 | 预览配置位置 |
|---|---|
| Windows | `%LOCALAPPDATA%/AccountPreview/project.json` |
| macOS | `~/Library/Application Support/AccountPreview/project.json` |

它指向本项目和本项目 `.venv`；匹配 helpers 由 `.runtime/helpers.json` 指向版本目录。此时不使用 `--initialize-identity` 或 `--enable-publish`，不需要云端凭据。

### 绑定冲突和重复配置

桌面绑定决定 App 读取哪个本地账本，与仓库访问权限无关。同一个系统用户的同一安装身份只有一个绑定。默认遇到其他目录会拒绝覆盖；本人确实迁移或切换自己项目并授权后，先关闭 App、停止其他配置操作，再使用旧绑定的绝对路径显式改绑，不删除配置：

```text
.\bootstrap.ps1 --apply --expected-root ROOT --configure-desktop --rebind-from OLDROOT
sh ./bootstrap.sh --apply --expected-root ROOT --configure-desktop --rebind-from OLDROOT
```

工具核对当前绑定等于 OLDROOT，在同目录保存 `project.json.backup-*` 原字节副本，再切换到 ROOT；输出 `desktop.backup` 为恢复位置。它不迁移旧账本、不更换安全身份或配对。旧根不匹配、配置无效或检查时发现配置变化会停止；锁只协调 bootstrap，不能保证拦住 App 或其他编辑器同时保存，因此须在关闭 App 后单独执行。PS/sh 首次运行可能已准备 uv/Python 缓存再发现绑定冲突，这些缓存可保留重试。不同人应使用各自系统账号/隔离环境，不通过改绑共用同一安全身份。

bootstrap 可重跑，但不是所有步骤都会跳过：Python 会重新核验并同步锁定依赖；组件重新校验哈希；相同桌面绑定返回 `unchanged`；显式选择 `--install-app` 会再次运行安装。它不重新 init 账本。输出 `steps` 按 `python/components/desktop/app/native` 分列 `requested` 和 `status`：预检为 `planned`，已执行为 `completed`，相同绑定为 `unchanged`，未选为 `skipped`。失败时保留已完成的环境和有效数据，按报错续接；不要清空 `.runtime`、重建账本或猜测未输出的步骤已完成。

### 与已有 Account 共存

| 项目 | 原个人版 personal | 独立试用 preview |
|---|---|---|
| 应用名 | Account | Account Preview |
| 桌面/Android 标识 | `com.account.probe` | `com.account.preview` |
| Windows 默认安装目录 | `%LOCALAPPDATA%\Account\` | `%LOCALAPPDATA%\Account Preview\` |
| Windows 桌面绑定 | `%LOCALAPPDATA%\AccountDesktop\project.json` | `%LOCALAPPDATA%\AccountPreview\project.json` |
| Windows 原生数据/安全存储 | `%APPDATA%\com.account.probe\` | `%APPDATA%\com.account.preview\` |
| macOS 安装目录 | 当前无 personal Mac 交付 | `~/Applications/Account Preview.app` |
| macOS 绑定/原生数据 | 当前无 personal Mac 交付 | `~/Library/Application Support/AccountPreview/project.json` / `~/Library/Application Support/com.account.preview/` |

安装目录可由用户自定义，以实际安装信息为准；Keychain/系统安全存储也按应用身份隔离。两套身份可以共存，但更新必须沿用原 profile 和签名，不用 preview 覆盖 personal，不卸载删除数据。首次绑定完成并不代表已经安装或实际打开 App。

macOS 内部包使用 ad-hoc 签名，未经 Apple 公证，见 [Tauri 说明](https://v2.tauri.app/distribute/sign/macos/)。首次阻止时由本人按 [Apple 步骤](https://support.apple.com/en-us/102445)，在“系统设置 → 隐私与安全性”为 Account Preview 选择“仍要打开”，不关闭全局防护。来源不明、损坏或恶意软件提示时保留现场检查。

下文 `PY` 为项目 Python：Windows `.venv\Scripts\python.exe`，macOS `.venv/bin/python`；`ROOT` 为本项目绝对目录，由 Agent 替换并引用含空格路径。

```text
PY scripts/account.py --root ROOT doctor
```

核对本机路径、Python、SQLite、依赖、组件与桌面绑定。`cloud.state=unverified` 是当前工具的原始状态；未选同步时解释为“可选同步未启用”，不因此判定本地失败，也不声称云端已验证。

`desktop.installation=unverified` 表示 doctor 尚未检查实际安装/启动，不是“未安装”。`desktop.profilePresent` 仅反映对应身份配置文件是否存在；还应核对其目录、安装结果并实际打开电脑 App，不能把配置存在当作运行验收。

以上默认流程针对首次配置。续接已有项目时，先核对实际身份和两道发布门禁：已有同步配置不重置，也不能仅凭 `cloud.state=unverified` 就断言同步未启用。导入或刷新前说明现有门禁是否可能自动发布；仅获本地操作授权而发现发布已开启时，先处理授权范围，不直接执行会上传的步骤。

## 3. 选择一个月，建立观察阶段空库

先问“你想整理哪个月，有哪些本地账单文件？”推荐最近一个完整月，即上月。已发布 `0.4.0-preview.1` 的 App 仅展示本月和上月；新候选 `0.4.1-preview.1` 改为从本人最早预算生效月或交易月持续保留到当前月，不能把作者的九月起点套给新用户。新能力须使用同版源码和 App；旧版较早记录可入库供 Agent 分析，但不能承诺会出现在当前 App 页面。不能为展示改交易日期或系统日期。记录实际平台与期间覆盖，不把部分文件说成整月全部支出。

首次只需解释“先看支出，再决定是否做预算”，不要求用户给四个额度或先做完整访谈。观察期不代表每月只能花 0 元；分池仍须在首批审核完成。新接口仅供同版源码及 App，旧发布版按其同版文档操作。

仅新初始化账本采用此模式；已有账本、确认额度、规则、身份及原有计算方式保留，不根据既有零值猜测含义，不自动迁移。需要显式额度输入时仍可使用[现有模板](../templates/预算额度.json)，原 `--amounts 本机文件.json` 用法继续支持。

```text
PY scripts/account.py --root ROOT init --effective YYYY-MM
PY scripts/account.py --root ROOT init --effective YYYY-MM --apply
PY scripts/account.py --root ROOT verify
PY scripts/account.py --root ROOT refresh --apply
```

`YYYY-MM` 使用确认的记账起始月，不晚于首批最早交易月份。先预检，已有本地建库授权时继续执行。重复初始化不覆盖已有账本。

初始化后，Agent 合并补充本机 `local/档案.md`，保留原有内容：

- 使用阶段：mini 本地观察。
- 预算状态：未制定；新账本默认零额度，采用观察模式。
- 初始滚存：零；没有历史结转承接。
- 分类/分池：首批按证据完成主分类和分池；真实歧义注明原因与后续待确认事项。
- 手机与同步：未启用（可选）。

程序生成的档案仍可能只有基础字段，以上个人状态由 Agent 补入。新库观察期显示“未设预算”及“设置 → 四池预算”入口，实际分池消费照常展示，但不产生超支、滚存欠账或安全积累。首次正数额度开始的月份（或明确提供非零初始滚存）启用预算；启用后即使后续额度为零，也按正常预算计算，详见[四池预算设置](四池预算设置.md)。已有未标记账本不因零值自动获得观察模式。累计图始终包含全部本人净消费、尚未分池记录和退款。不能为提示虚构额度、改消费口径或猜测分池；真实交易金额缺失不得补零。

## 4. 首批记账并在电脑查看

由本人选择一个月的本地 CSV/XLSX 文件并授权本批记账。Agent 先按[原件归档约定](工作说明.md#原件归档)确认 ROOT 内 `sra/`，把所选文件复制到此处并核验 SHA-256；保留下载夹等位置的原文件，同名不同内容不覆盖。prepare 只读引用归档路径，不要求先用手机上传。再按工作说明完成审核、import 预检、显式写入和核验，生成本机快照。审核字段合法值见[数据字典](数据字典.md#审核字段取值)，不要套用旧 Excel 的中文口径别名。

首批先判断本人真实承担的净额、转账、退款和报销关系，再按证据完成主分类和分池；这项审核不是可跳过步骤，也不依赖预算额度。通用用途定义与虚构例子见[记账规则](记账规则.md#主分类与分池)。无需先建立完整私人分类体系，不按商户、金额或主分类机械分池。本人已确认的个别分配优先保留，退款继承已确认原交易的池。

高影响或反复歧义先问；低影响且用途确实不明时，可保留实际消费金额、解释待定原因并留待归类，不猜测、不硬凑覆盖率。Agent 分别报告主分类和资金池已分配/待确认的笔数与金额及原因，不能整批待定却声称分类分池完成；未确认事件或净额的候选单独报告。核验后引导打开电脑 App 查看净额、分类和真实分池消费；观察阶段显示“未设预算”，不以预算余额评价这个月。

## 5. 看完以后，做一次简短访谈

按[规则与学习](规则与学习.md)先问两三个问题，例如：“哪块支出最出乎你的意料，接下来想留意？”“这些分类有没有不符合你习惯的？”允许回答“不确定，先记着”。

第一轮只整理关注点和少量分类修正，不要求立刻给预算、不预设消费约束、不把关注意向自动升级为长期规则。需要保存规则、修改历史或增加正式预算时，再确认范围和依据。mini 阶段不承诺适合所有人的完整分类或支出管理。

导入后即能查看完整净消费、日历、分类和明细，不受预算是否制定影响。以后希望设额度时，进入“应用设置 → 四池预算”，可以把首次额度设为导入账单的月份，不必等待下个月。先预览新旧额度及影响月份，再确认保存；额度从生效月沿用至下一条额度前。修改已存在的生效月会重算该区间及后续滚存，原始交易不变，旧额度与确认依据保留在审计中。详见[四池预算设置](四池预算设置.md)。

## 6. 本地完成；扩展以后选择

完成标准：项目环境和桌面绑定正确，独立账本核验通过，本人选择的首批账单已按授权处理，完成有依据的主分类与分池并说明真实待定项，电脑能查看有效结果，访谈结论或“暂不决定”已记录。若暂未提供账单，可报告“本地环境与空库就绪，等本人选择文件”，不能虚报首批入账。

交付时分开报告：“本地可用 / 预算未制定 / 手机与同步未启用（可选）”；后两项不阻塞基础体验。本人希望手机查看或投递账单时，再按[手机与同步](手机与同步.md)建立同步身份、安装 Android、配置坚果云、配对和授权发布。启用时沿用现有账本，不重做此前步骤。

隐私小注：账单、账本与个人规则默认保存在本机，不提交共享仓库。本人授权的 Agent 如调用云端模型，读到的内容可能按其设置发送给模型服务；可选手机上传还会经坚果云加密中转，详见[同步与隐私](同步与隐私.md)。
