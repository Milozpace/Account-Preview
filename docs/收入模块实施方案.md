## 一、现状核查结论（以当前代码为准）

### 1.1 现有口径与校验链

| 事实 | 出处 |
|---|---|
| 非零 `计入消费金额` 只允许 `PERSONAL` / `PROJECT` / `STRUCTURAL`，否则计算直接报错（`INCOME` 带非零消费金额也会被拒） | `ledger_calculation.aggregate()` |
| `EXCLUDED` 是零金额口径，写排除依据，不进快照明细 | `docs/数据字典.md` |
| `资金池` 只允许空、四池、`待归类`；安全积累是计算结果不是池 | `account.normalize_record` / `ledger_store._validate_state` |
| `最终财务事件` 是自由文本（`purchase`/`refund`/`transfer`/`reimbursement`），事件名不能代替口径 | `docs/数据字典.md` |
| `主分类` 自由文本，无固定分类体系 | 同上 |
| 新增记录必须显式提供：`最终财务事件`、`统计口径`、`计入消费金额`、`主分类`、`资金池`、`语义说明` | `ledger_store.import_reviewed` |
| `原始金额` 必须显式提供（不能缺失/占位补零）；`退款调整`/`净支出候选`/`计入消费金额` 为整数分列 | `ledger_store.MONEY_COLUMNS`、`account.raw_money` |

**关键发现：口径为 `INCOME`、`计入消费金额=0` 的记录，当前全链路已经天然容忍**——`aggregate()` 只对非零消费金额做口径白名单检查，`build_month()` 会跳过零金额行。即收入行今天就能安全入账（只是无处展示）。这让改动可以做到最小。

### 1.2 收入金额如何可靠计算

- `原始金额`：账单原始符号，工资/经营收款到账为正数。
- `净支出候选`：只是展示参考列，**代码从不校验它等于 原始金额−退款调整**，不可靠。
- `退款调整`：已有列，用于在原交易上记冲减。
- **收入金额契约（已定案）：收入金额 = 经审核的实际到账金额（`原始金额`）。**
  - 不用消费用途的 `退款调整` 字段作为收入净额计算规则（校验拒绝收入行携带非零 `退款调整`）。
  - 收入冲回不是第一版常规功能：错误入账、工资追回等用有证据、关联原收入行的负向收入记录净额化（事件 `income_reversal`、`关联记录ID` 指向原行），避免重复冲减。
  - 不碰 `计入消费金额`（消费口径专用，污染消费统计）；不加新字段、不加复杂机制，保留扩展空间。
- 不复用消费金额列，不新增持久字段。

### 1.4 合成样例中工资标记为 STRUCTURAL 的情况（已按要求核查）

- `tests/fixtures/app-v2-snapshot.json`、`app-v2-history-snapshot.json`（Python/TS/Rust 三端共享 fixture）：每月一条 `合成工资入账`，`scope=STRUCTURAL`、`category=收入结转`、`amountCents=-800000`（负结构性，旧模型用负数表达收入流入）。

- 这些都是**测试/预览合成数据，不是真实账本历史**，可以调整（用户已认可）。**落实时点在快照/展示阶段**，本轮 fixture 保持原样。

## 二、本轮范围（隐形实现：外观与数据零可见变化）

只动 Python 数据层 + 测试 + 文档/Skill。**不改任何快照格式、不改 Rust、不改前端**，双端 0.3.15 行为完全不变。

### 2.1 INCOME 口径的写入校验（`ledger_store._validate_state`）

对 `统计口径=INCOME` 的行新增校验（现有账本无 INCOME 行，不影响存量数据）：

1. `计入消费金额` 必须为 0 或空（收入不得进入消费统计；显式报错而非静默容忍）。
2. `资金池` 必须为空——收入不分配四池，也不允许 `待归类`。
3. `主分类` 必填（导入管线已要求，校验层补一道防线）。
4. 收入金额 = `原始金额`（实际到账）；`退款调整` 必须为空，冲回走负向收入记录。
5. `EXCLUDED` 的互转/报销/借款等行为完全不变，收入聚合天然忽略它们。

### 2.2 收入聚合（`ledger_calculation.py`）

新增独立函数（不改 `aggregate()` 一行既有逻辑）：

```python
def income_aggregate(rows):
    """按月返回 {'YYYY-MM': {'income': cents, 'count': n, 'categories': {主分类: cents}}}"""
```

- 只取 `统计口径=INCOME` 的行，金额 = `cents(原始金额)`（实际到账金额，负向记录自然净额化）。
- `calculate_month()` 返回的内部计算契约增加 `income` 块（total/count/categories），供测试断言、后续展示阶段直接消费；本轮不进快照。
- `calculation_version` **不变**：消费、预算、滚存、安全积累的计算规则一字未动；收入聚合是新增展示派生。业务 `sourceHash` 机制不变（新增收入行会通过 rows 自然改变哈希，无需特殊处理）。

### 2.3 CLI 可见性（`ledger_store._describe` / inspect）

`inspect` 的月度聚合输出增加 income 合计，作为本轮唯一的收入可见出口（命令行核验用，不影响任何客户端展示）。
