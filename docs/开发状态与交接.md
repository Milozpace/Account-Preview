## 当前能力与关注点

SQLite 是唯一账本；统一 Python 计算消费、四池和独立 INCOME 收入；浏览器读 Web 快照，桌面通过 bridge 读原生校验的 App 快照，Android 读加密 App 快照且不直接写账本。收入候选采用 Web schema 2 / App schema 3；公开 preview.4 采用 1 / 2，升级必须看[快照与月份](快照与月份.md)。手机收入入口尚不在已实现范围。

本轮已补收入审查的三项修复与回归：income_reversal 强制负号/原始正向收入关联，inspect incomeCents 返回整数分，Python/Rust 校验分类集合及零净额分类完整性；准备回执包含收入笔数。原始来源为正金额支出表达追回时，第一版不允许改负原始金额，保留来源并暂缓相关收入冲回分类。

发布器可严格识别已认证的旧 App 2 历史，升级到更高 revision 的 App 3；旧 pending 不能直接上传。消费者和 stage 仍严格使用 App 3，不补零展示旧收入数据，未知/损坏/外来契约继续拒绝。具体升级矩阵和执行顺序见[快照与月份](快照与月份.md)。

版本工具同源生成 App、Dashboard 及 Python 适配元数据，新 personal-local 使用统一索引；旧 0.3.x 索引和旧预览安装下限保持保护。新版更新器才支持新统一索引；未实现多渠道远端自动订阅，现有 preview 订阅不变。

共享程序、app/helper、更新器和版本工具的测试均使用合成数据。个人安装先快后稳通过渠道与候选实现，保持个人/朋友身份、签名、配置、配对、云命名空间和数据隔离，不长期复制两套核心代码。

## 续接顺序

1. 先检查当前分支和未提交改动，再读[开发同步与发布规范](开发同步与发布规范.md)、[架构与部署边界](架构与部署边界.md)及本次涉及契约。
2. 功能/修复回 dev；旧公开版本问题从相应 tag/维护线修，再回流 dev。已发布版本不复用为修改后的构建。
3. 验证后更新本页的本轮结果、仍待验收范围和证据入口，主动提交本次文件。实际安装、远端推送与 Release 按授权单独记录。
4. 本地审查、方案和个人安装历史不复制进公共 fixture 或本页；可在本机开发环境入口保留路径。

## 本轮验收边界

新增回归覆盖收入约束与单位、零净额分类、旧 App 2 缓存/双槽/pending 升级、8 MiB 契约边界、首次采用的产品/原生/Android 降级保护、旧索引认证来源恢复及同版 Skill 续接。规范与代码均经独立审查，具体测试数量随本轮完成回执记录，不以旧测试次数推断新提交。

本轮是本地开发与合成升级验证，未将此候选覆盖安装到个人或朋友设备，也未写真实账本、发布云端展示或创建新 Release。既有 Windows 收入入口曾在上一候选实际查看；这不替代本轮新安装包的跨设备验收。Mac、Android 以及真实同版 app/helper 覆盖交付仍应在正式交付前按[发布检查](发布检查.md)验收。
