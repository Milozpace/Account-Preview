# 日常工作说明

`data/account.sqlite3` 是唯一当前账本，`data/source.json` 选择 SQLite。缺库/来源异常时停止，不回退旧表格或演示数据。网页和 App 快照统一由 Python 计算，缓存不是第二套账本。

| 位置 | 职责 |
|---|---|
| `data/account.sqlite3` | 流水、预算、生效月、滚存、批次与审计 |
| `sra/` | 原始账单，只读保留 |
| `local/档案.md` | 当前用户的本机配置和偏好 |
| `local/个人规则.md` | 用户批准的个人规则和适用边界 |
| `PROJECT_MEMORY.md` | 本机工作摘要，不替代证据 |
| `.runtime/` | 审核候选、恢复副本、快照、原生组件、同步状态 |
| `docs/` | 可分享通用说明，不放真实明细与身份 |

个人资料、账本、原件、缓存、凭据和产物不提交。不清空整个 `.runtime`，不删除原件。

## 第一轮 mini：先看一月记录，再了解需要

先按[开始使用](开始使用.md)准备电脑本地环境。本人选择近期一个月的本地文件并授权该批记账，不以手机、云端或四池额度齐备作为前提。推荐上月完整月；旧 `0.4.0-preview.1` 仅显示本月和上月，`0.4.0-preview.2` 起按本人账本起点持续保留月份，须使用所选已发布标签的同版源码与 App。如文件覆盖不全，说明实际平台/日期范围。

先解析去重，审核事件与净额，再按用途证据完成主分类和四池分配；首次分类分池不能跳过或等预算设定。无需一开始建好完整分类和私人规则，按[记账规则](记账规则.md#主分类与分池)的通用定义即可，不按主分类、商户或金额机械映射。高影响或反复歧义先问，低影响确实不明可解释后待归类，保留真实金额；连事件/净额也不明的保留待审核候选并单独报告，不为批量完成编造结论或硬凑覆盖率。保留本人已确认的个别分配，退款继承已确认原交易池。

`0.4.0-preview.2` 起 init 可省略 amounts，新空库默认全零额度、零滚存，并记录 zero-observation-v1 观察模式。本机档案标“预算未制定”，UI 显示“未设预算”及“设置 → 四池预算”入口。观察期实际分类及分池消费可见，但不产生超支、滚存欠账或安全积累；首次正数额度或明确非零初始滚存启用后，后续零额度也按正常预算计算。已有未标记账本保留原计算与哈希，不从零值猜意图或自动迁移。不能用零预算替代缺失交易金额，或为预算显示改消费口径。

核验入账并在电脑查看净额、交易与主分类后，按[规则与学习](规则与学习.md)做两三个简短访谈，了解想关注的支出和分类不适配之处。允许“先继续观察”，不强迫给出预算。用户希望控制某块支出只记录为关注意向，不自动修改预算或生成长期规则。

## 一次记账

“帮我记账”可授权该批审核入账，纯讨论只读。按[开始使用](开始使用.md)替换 `PY` 和 `ROOT`。

### 原件归档

首次 prepare 前，核对本人选定的 ROOT，确认/创建其下 `sra/`（初始化通常已创建）。归档目录不得是指向其他目录的符号链接或 junction。仅复制本人选择并授权处理的文件，保留下载夹等来源文件，不移动、不重存、不改编码。计算复制前后的来源 SHA-256，并与归档文件 SHA-256 核对一致；若复制期间来源变化则停止，保留现场重新核对。同名同哈希可复用；同名不同字节另取明确文件名（可加哈希后缀）或询问，不覆盖旧件。文件名中的私人内容不写进共享文档/Issue。

后续 prepare 使用 ROOT/sra 内归档的绝对路径，完整保留审核 JSON 的 `source_files` 路径和哈希；归档只读引用，不删除原件。手机收件工具已校验归档的文件同样引用其归档路径，不再制造另一份不同字节的“原件”。

```text
PY scripts/account.py --root ROOT doctor
PY scripts/account.py --root ROOT inspect
PY scripts/account.py --root ROOT prepare --source ROOT/sra/归档账单.csv --output .runtime/本批审核.json
PY scripts/account.py --root ROOT import --input .runtime/本批审核.json
PY scripts/account.py --root ROOT import --input .runtime/本批审核.json --apply
PY scripts/account.py --root ROOT verify
```

prepare 只生成候选。Agent 根据通用/个人规则和原始证据审核，填写审核者、时间及依据，解决冲突后预检。高影响歧义先询问，证据不足留 Unknown；空金额不补零，已有人工确认不自动覆盖。

`import --apply` 写前通过 SQLite Backup API 留存恢复副本，整批事务校验提交，失败回滚。成功后核验完整性、ID/关联、来源、净额、汇总、预算和快照；同一审核文件再预检应无新增/更新。汇报真实结果。

## 手机投递（可选扩展）

未选手机与同步时，此节跳过；按[手机与同步](手机与同步.md)完成扩展后才使用，不阻塞电脑本地记账。

手机“我的 → 上传原始账单”加密投递 CSV/XLSX，不改账本。Agent 按授权执行 `inbox-fetch --apply`，校验归档后，以归档文件 prepare。`inbox-status` 只读本机状态；`inbox-receipts --apply` 核验入账证据后重试回执，参数见 `--help`。

上传、收取、SQLite 提交、快照发布、回执、手机显示是不同状态。回执失败时重试回执，不重新导入已提交记录。详见[同步与隐私](同步与隐私.md)。

## 预算与修正

预算管理是观察后的可选步骤。本人明确希望启用且认为当前四池适合时，才讨论具体额度；主分类可以逐步调整，但当前资金池名称固定，不声称支持任意自定义资金池。

额度只在库内按生效月维护，从该月起继承至下一条额度前；无需每月重复设置。常规 budget 命令仍只追加；本人明确修订或首次采用预算时，可以通过“应用设置 → 四池预算”或 budget-set 在导入月份设定额度。先读取当前哈希、预检影响月份，再确认写入；事务内修改、写前备份、保存前后额度及确认依据审计，不绕过工具直接 SQL。历史额度调整会影响后续滚存/安全积累，但不改交易字段。见[四池预算设置](四池预算设置.md)。

额度保存只重建本地展示，不隐式发布云端。保存成功和展示更新分别报告；如快照失败，保留已提交额度，重新读取后处理，不能反复写入。通常导入/刷新仍按既有发布门禁工作，云端更新另按授权。

新库观察阶段显示“未设预算”，实际消费、累计净消费、日历、主分类和分池正常展示；预算额度可选，首次分类分池必须按证据完成，真正未定项说明后待确认，不靠猜测填入。普通使用者 Agent 只通过正式工具记账/修改参数和更新发布程序，不改共享源文件或界面。

修正用显式 `updates`，附理由和确认出处，留前后值审计。推广长期规则另按[规则与学习](规则与学习.md)取得明确批准。

## 结果报告

报告期间、新增/更新/重复/待确认笔数、净消费、主要分类、验证/幂等和电脑查看结果。分别报告主分类与资金池已分配/未完成的笔数、净消费金额及待定原因，金额保持退款符号；不能以整批待定或无解释的空字段声称分类分池完成。mini 说明“预算未制定，观察期不计算超支、滚存欠账及安全积累”；已启用预算时报告实际四池影响。手机与同步未选时标“未启用（可选）”；选用后再分报快照、云端回读、回执和设备。账本成功但云端失败时保留成功账本与上一有效快照，不声称手机已更新。
