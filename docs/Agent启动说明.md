# Agent 启动说明

本页用于首次配置或配置中断后的续接。完整参数与异常处理见[开始使用](开始使用.md)。已配置账本的日常任务从[记账 Skill](../.agents/skills/account-maintenance/SKILL.md)开始。

## 执行顺序

| 步骤 | Agent 检查与执行 | 完成依据 |
| --- | --- | --- |
| 定位 | 核对本人授权、绝对 ROOT、系统架构、来源、原安装身份及现有账本 | 实际路径和文件状态 |
| 选版 | 读取最新入口，选择已发布 Release 的同版源码和组件 | tag/索引、提交、哈希、profile |
| 准备环境 | 从 ROOT 执行同版 bootstrap 预检，带匹配 expected-root 按授权执行 | steps 中各步骤的实际状态 |
| 安装与绑定 | 检查原绑定，核对匹配 App/helpers 和项目 Python | 配置指向、安装结果 |
| 账本分流 | 运行 doctor，已有库 verify，确认为新项目才预检/init | setup、source.json、SQLite 核验 |
| 首批记账 | 本人选择月份和文件后，按随版 Skill 连续审核、入账、核验 | 本批来源、批次、verify/幂等结果 |
| 查看与收尾 | 实际打开 App，核对导入月，简短了解偏好 | 实际页面和待定项报告 |

只有已授权的步骤才执行写入。已有执行授权且路径和范围明确时连续完成。目录不明、真实净额/关联疑问、超出本次云端授权等情况，说明具体缺口再请本人决定。

## 续接时先辨认实际状态

- 缺个人文档时，先核对库及来源，再补状态指针。
- doctor 的顶层 ok 表示检查成功，还须看 setup、依赖和 helpers。
- profilePresent 仅说明配置存在，installation=unverified 需要实际安装与页面核对。
- cloud.state=unverified 表示尚未验证，须结合既有双门禁解释。已启用同步的项目在 import/refresh 前核对授权范围。
- 绑定冲突按原根和明确迁移授权使用 rebind-from，保留旧配置备份。
- 未提供文件时报告环境/空库就绪。已入账后处理失败时先核对提交结果，再处理快照或回执。

## 配置完成后

本地可用后按[规则与学习](规则与学习.md)做简短访谈。预算走[四池预算设置](四池预算设置.md)，手机扩展走[手机与同步](手机与同步.md)，继续同一本账。

交付时说明本地结果、真实待定项和未执行的设备/云端步骤。私人文件、原件与状态留在本机，相关隐私范围见[同步与隐私](同步与隐私.md)。
