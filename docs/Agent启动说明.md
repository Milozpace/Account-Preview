# Agent 启动检查：mini 本地优先

先读 README、`AGENTS.md` 和[开始使用](开始使用.md)。默认目标是“本人提供一个月本地账单 → Agent 审核记账 → 电脑可视化 → 简短访谈”，不以手机和云端配置作为完成前提。

1. 检查系统与授权范围，公开仓库无需邀请或登录。选定长期保留的普通目录，核对完整绝对根及 bootstrap 预检来源；不可把同名开发目录误作本次 clone。新启动器 apply 必须带 --expected-root ROOT；已有明确授权不重复确认。
2. 使用对应 bootstrap 准备托管 Python、匹配电脑版包/helpers、安装及桌面绑定，执行 doctor。无需开发工具链、专属 Skill 或额外模型 API。
3. 询问近期月份和本人愿意提供的本地文件，推荐完整上月以便当前 App 展示；说明文件覆盖范围。不先要求四池额度、完整分类方案或详细生活访谈。
4. 全新账本在说明含义后，按开始使用采用全零技术占位初始化、零滚存，并在本机档案记录“预算未制定 / mini 本地观察 / 同步未启用”。已有账本与参数保留；不能重置或猜测已有零值的意图。新配置 verify 后本地 refresh，保持发布门禁关闭；续接已有项目先检查实际身份和门禁，不误报未启用，导入/刷新前说明可能自动发布并核对授权。
5. 占位只是兼容当前初始化接口，当前 CLI/UI 未实现真正的无预算状态。不得据占位判断超支、虚构大额度、强行分池或补零真实金额。主分类可从少量直观名称开始；资金池未定可“待归类”，但真实消费金额与统计口径须符合证据。高影响净额疑点先问，低影响歧义合并询问或暂留。
6. 在已获本人记账授权的文件范围，先按工作说明把原件复制归档至本项目 sra/、校验哈希且不覆盖，再 prepare → 实际审核 → import 预检 → apply → verify/本机快照，核对退款、去重和分类，在电脑 App 查看。未提供文件时只报告环境/空库就绪。
7. 再做两三个简短访谈，了解想关注的支出和分类不适配之处。允许暂不制定预算；关注意向不等于额度或长期规则。个人结论仅记本机，推广规则和历史重判各自确认。
8. 本地完成后明确报告结果，以及“预算未制定”“手机与同步未启用（可选）”。doctor 的 desktop.installation=unverified 不等于未安装，需实际打开 App 验收；bootstrap 的 steps 按请求与实际状态报告，不能把 skipped 当已执行。cloud unverified 保留原含义，不能当作本地失败或云端已通过。后续本人选手机时才进入[可选指南](手机与同步.md)，建立同步身份、配置两端凭据、扫码，获准后开双门禁、发布回读；不要重新建库或重复导入。
9. 原件、SQLite、个人规则不提交共享仓库。说明所用 Agent 的云端模型可能处理读到的内容；启用手机上传后原件会有坚果云加密副本。详见[同步与隐私](同步与隐私.md)，不承诺任何场景下文件绝不离开设备。

后续开发验证通过后主动提交相关代码，安装、真实改账、同步、配对及远端操作按实际授权连续完成。没有设备或未执行的功能不声称通过。
