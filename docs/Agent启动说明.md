# Agent 启动检查：电脑本地优先

此文仅用于首次配置，不是日常记账流程。先读 `AGENTS.md` 和 [开始使用](开始使用.md)，默认完成“本地环境 → 本人一月账单 → 电脑查看”，手机与云端以后选择。无需外部安装 Skill 或额外模型 API；仓库已带官方日常 Skill，首批导入时必须读取。

1. 核对系统、授权和本人选定的长期绝对 ROOT，预检源码来源。缺 `PROJECT_MEMORY.md` 或个人文档不能判定未初始化；先以 doctor、来源文件及 SQLite 判断。旧根/已有账本保留，不从其他目录找私人资料。
2. 按入门文档准备托管 Python 和同版电脑包/helpers，bootstrap apply 带 `--expected-root ROOT`。桌面绑定冲突显式使用获准旧根 `--rebind-from`，不删配置、不换身份。已授权配置连续完成，不重复确认。
3. 仅确认为全新项目时按入门文档建立观察空库，可省略 amounts、采用零额度和零滚存；已有账本/参数/计算哈希不重置或自动迁移。生成的本机文档只是实际状态和证据指针，保留原有所有者内容，不把流程抄进模板。新阶段可标“预算未制定”，同步状态以实际配置为准。
4. 本人选择月份/本地文件并授权本批记账后，**交给 [account-maintenance Skill](../.agents/skills/account-maintenance/SKILL.md)**。首批与后续使用同一审核、分类分池、写入及核验流程，不在此另维护一套。缺预算不跳过有依据的分类与分池；未提供文件仅报告环境/空库就绪。
5. 实际打开电脑 App 核对本地结果，再按 [规则与学习](规则与学习.md) 做两三个简短访谈，允许暂不制定预算。预算设置走 [四池预算设置](四池预算设置.md)，个人关注不自动成为额度或长期规则。

bootstrap 的 `steps` 按请求/实际执行报告，skipped 不是已完成；doctor 的 `desktop.installation=unverified` 不表示未安装，配置存在也不是运行验收。`cloud.state=unverified` 不是本地失败或云端通过。已有项目先核对真实身份与门禁，导入/刷新可能自动发布时核对授权；不能误报同步未启用或重置门禁。

手机、云端、配对和发布只在本人选择后按 [手机与同步](手机与同步.md) 续接现有账本；不重新初始化、不重复导入。私人文件不提交；Agent 所选云端模型可能处理读到的内容，手机上传经坚果云加密中转，见 [同步与隐私](同步与隐私.md)。设备未验收和未执行步骤如实报告。
