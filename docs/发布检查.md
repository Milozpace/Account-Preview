# 预览发布检查

面向维护者，每次留版本、构建来源、产物、SHA-256、系统/架构、时间及通过/失败/未执行项。清单不能替代实测。

- [ ] 包无个人账本/原件/档案/规则/记忆、真实缓存/日志、凭据/生产身份。
- [ ] 忽略和隐私扫描覆盖数据库 sidecar、导出、备份、缓存、产物、安全配置。
- [ ] Python 固定依赖、前端/Rust 锁文件可重现，合成测试与构建通过。
- [ ] release.json 版本、原生版本和 Android buildCode 一致且递增，`release.py version-check`通过；各平台和 helpers 的版本、源码提交、身份、名称匹配。
- [ ] Windows 新目录引导、doctor、init、verify、安装/绑定/启动。
- [ ] macOS 同上，路径/权限/签名/首次打开实测。
- [ ] 合成导入/去重/冲突/回滚/备份恢复、个人隔离、旧确认保护。
- [ ] 双端覆盖安装保留配置/密钥/配对/偏好，文件选择/取消实测。
- [ ] 独立身份实测发布回读、手机刷新、账单投递/收取/入账/回执。
- [ ] 多用户/根互不覆盖，无模型 API 或必装 Skill 假设。
- [ ] 无历史上下文 Agent 演练，缺权限/产物/配置准确报告。
- [ ] 默认 mini 本地入口：先选近期一月文件、核验记账和电脑查看，再做简短访谈；预算未制定与手机未启用不阻塞基础完成。
- [ ] 新库零预算仅技术占位，个人档案明确状态，不据占位判断超支，不强分池、不把缺失交易金额补零；已有账本参数保留。
- [ ] preview 四平台及 personal Windows/Android 六个身份/平台组合齐备，个人签名与原版相同；不可拿 preview 包覆盖个人版。
- [ ] 固定干净 commit，源码 ZIP 与该 commit 一致；release-manifest.json、用户本人 notes 和 SHA256SUMS 齐备，候选 Artifact 不是 Release。
- [ ] 已取得维护者针对本版的明确发布确认；本人 notes 非空且无模板占位，不由 Agent 生成文案；已发布 tag/包不可替换。
- [ ] 更新器合成升级、两用户隔离、路径/哈希/冲突拒绝、幂等、备份和失败恢复通过；实际 OS 安装/覆盖保护另报告。

未执行标待验收，单平台构建不代替跨平台/真机。未发布不编造地址。已授权开发验证后主动提交相关代码，不另询问提交许可；远端推送与发布按任务实际授权，已授权事项连续完成。

手机、配对、云端和回执作为可选扩展单独列结果；本人未选时写“未启用”，不判定本地引导失败。发布时仍如实说明扩展是否经过本版本实测。文档 mini 流程不等于已新增无预算界面、自定义资金池或完全离线的 Agent。

## 远端验证与定向重试

默认 push/PR 验证全部平台。需要定位或重试单个平台时，手动执行 `gh workflow run verify.yml --repo Milozpace/Account-Preview -f platform=macos-x64`；可选 `all`、`windows-x64`、`macos-arm64`、`macos-x64`、`android-arm64`。定向执行仍完整运行该平台的测试、引导和构建，不能把未执行的平台计为通过。

保留产物对应的源码提交与成功 job。只修改 CI/测试时，复用此前其他平台产物须核实应用运行时代码未变，并在本轮记录列明各自来源。Mac 临时测试 Keychain 应明确解锁，测试所需系统交互须失败或超时，不能在无人值守环境无限等待；不更改真实用户钥匙串来使测试通过。

## Android 签名与构建产物

CI 的 Android artifact 是未签名构建候选；维护者验证后用同一份离线维护的预览版签名密钥签名，再生成最终 APK 的校验值和分发包。签名私钥及其密码不进入源码、Artifact 或 Release。预览版使用独立应用标识和签名，不能拿生产版密钥或配对来代替。

后续覆盖升级沿用首次分发的签名；协作者提交代码不代表各自创建不同签名的安装包。不要将 CI 的 unsigned 文件作为朋友可直接安装的版本。
