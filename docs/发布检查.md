# 预览发布检查

面向维护者，每次留版本、构建来源、产物、SHA-256、系统/架构、时间及通过/失败/未执行项。清单不能替代实测。

本地候选用于获准的本机验收，可以先于远端 tag/Release；这种版本差异本身不表示流水线失败。本机验收通过是发布输入，正式发布仍须满足下列条件及维护者针对该版的确认；普通使用者继续只安装已发布的匹配版本。

先核对[版本与分支管理](版本与分支管理.md)和[开发状态与交接](开发状态与交接.md)，不从旧计划或工具记忆推断当前发布状态。

- [ ] Release 有本次更新、升级说明、给 Agent 的更新指引；累计衔接指引与同版源码一致，入口及重复更新可发现，不能把程序安装等同业务衔接完成。
- [ ] main/dev/短期分支来源与目标明确；冻结候选只收修复，旧版修复已回流或明确列为尚待回流，不夹带未完成开发功能。
- [ ] 产品版本、渠道、安装身份、commit/build、原生序号及实际安装状态分开记录；同源 personal/preview 产品版本一致，旧独立个人版本只作兼容历史。
- [ ] 普通提交不建发布 tag；公开 tag 固定已批准交付，旧标签和资产不移动/替换，本地候选回执不冒充公开 Release。
- [ ] 快照/协议变化已检查新旧客户端、旧本地缓存、旧云端、离线及 helper 混装；说明升级顺序和恢复路径，手机 UI 不变不等于无解析升级要求。

- [ ] 包无个人账本/原件/档案/规则/记忆、真实缓存/日志、凭据/生产身份。
- [ ] 忽略和隐私扫描覆盖数据库 sidecar、导出、备份、缓存、产物、安全配置。
- [ ] Python 固定依赖、前端/Rust 锁文件可重现，合成测试与构建通过。
- [ ] release.json 版本、原生版本和 Android buildCode 一致且递增，`release.py version-check`通过；各平台和 helpers 的版本、源码提交、身份、名称匹配。
- [ ] Windows 新目录引导、doctor、init、verify、安装/绑定/启动。
- [ ] Windows PowerShell 5.1 全新环境在 `2>&1 | Select-Object -Last 20` 下完成引导，正常 stderr 进度不中断、原生非零退出码保留；核对完整结果，不能只依赖尾部输出。
- [ ] `--apply --expected-root` 错配在配置前停止；源码、原生组件与 helper 版本／身份匹配，升级保留账本、绑定和同步身份。
- [ ] macOS 同上，路径/权限/签名/首次打开实测。
- [ ] 合成导入/去重/冲突/回滚/备份恢复、个人隔离、旧确认保护。
- [ ] 双端覆盖安装保留配置/密钥/配对/偏好，文件选择/取消实测。
- [ ] Android 优化 APK 的扫码 registrar 构造检查通过；相机打开、返回按钮、系统返回与重复进入均实测通过。
- [ ] 独立身份实测发布回读、手机刷新、账单投递/收取/入账/回执。
- [ ] preview 三通道使用 Account-Preview，personal 保持 Account；旧目录确认与恢复证据不跨目录使用，外来或无法认证的文件仍拒绝覆盖，并存验证保护原正式目录。
- [ ] 多用户/根互不覆盖，无模型 API 或必装 Skill 假设。
- [ ] 无历史上下文 Agent 演练，缺权限/产物/配置准确报告。
- [ ] 默认 mini 本地入口：先选近期一月文件、核验记账和电脑查看，再做简短访谈；预算未制定与手机未启用不阻塞基础完成。
- [ ] 新库零预算仅技术占位，个人档案明确状态，不据占位判断超支，不强分池、不把缺失交易金额补零；已有账本参数保留。
- [ ] 公开 CI 与 Release 仅有 preview 三平台；personal Windows/Android 本机同源同产品版本构建，沿用个人身份和签名，不上传个人包或 Artifact；安装序号高于已装下限。
- [ ] 固定干净 commit，源码 ZIP 与该 commit 一致；公开目录恰有三套 preview 组件、源码 ZIP、release-manifest.json 和 SHA256SUMS 共六项。notes 在目录外，仅作为 Release 正文，不附 Markdown 原稿；用准备结果的 assets 白名单上传。
- [ ] 已取得维护者针对本版及 notes 最终稿的明确确认；说明由 Agent 起草后交本人润色或确认，非空且无模板占位；已发布 tag/包不可替换。
- [ ] 更新器合成升级、两用户隔离、路径/哈希/冲突拒绝、幂等、备份和失败恢复通过；实际 OS 安装/覆盖保护另报告。

未执行标待验收，单平台构建不代替跨平台/真机。未发布不编造地址。已授权开发验证后主动提交相关代码，不另询问提交许可；远端推送与发布按任务实际授权，已授权事项连续完成。

手机、配对、云端和回执作为可选扩展单独列结果；本人未选时写“未启用”，不判定本地引导失败。发布时仍如实说明扩展是否经过本版本实测。文档 mini 流程不等于已新增无预算界面、自定义资金池或完全离线的 Agent。

## 远端验证与定向重试

默认 push/PR 验证 Windows x64、Apple Silicon Mac 和 Android arm64。定向重试使用 `gh workflow run verify.yml --repo Milozpace/Account-Preview -f platform=macos-arm64`；可选 `all`、`windows-x64`、`macos-arm64`、`android-arm64`、`python-only`。Python-only 在 Windows 和 Apple Silicon 运行完整 Python 回归，不代替原生包发布检查。从 preview.5 起停止 Intel Mac 的 App、Python 引导和 CI 支持；历史验证记录与资产保留。

保留产物对应的源码提交与成功 job。只修改 CI/测试时，复用此前其他平台产物须核实应用运行时代码未变，并在本轮记录列明各自来源。Mac 临时测试 Keychain 应明确解锁，测试所需系统交互须失败或超时，不能在无人值守环境无限等待；不更改真实用户钥匙串来使测试通过。

## Android 签名与构建产物

CI 的 Android artifact 是未签名构建候选；维护者验证后用同一份离线维护的预览版签名密钥签名，再生成最终 APK 的校验值和分发包。签名私钥及其密码不进入源码、Artifact 或 Release。预览版使用独立应用标识和签名，不能拿生产版密钥或配对来代替。

后续覆盖升级沿用首次分发的签名；协作者提交代码不代表各自创建不同签名的安装包。不要将 CI 的 unsigned 文件作为朋友可直接安装的版本。
