# 同步与隐私

## 默认：电脑本地使用

原始账单、SQLite 账本、个人档案和规则默认保存在本人电脑，供本人及本人授权的 Agent 处理，不提交到共享 Git 仓库、Issue 或 Release。建议让能操作本地文件的 Agent 读取本人选择的本地路径；不要求把原件上传到聊天附件或其他平台。

**“本地保存”不等于所选 Agent 的处理也完全离线。** 如果 Agent 调用云端模型，它读取的账单内容可能按其产品和设置发送给模型服务；项目不控制该服务的处理、日志或保留方式。由本人了解并选择 Agent 的权限与设置，不能承诺“任何第三方都绝不接触”。反馈仅提供脱敏诊断或虚构样本，不附真实账本、原件、完整账号、密码或二维码。

未选手机扩展时，不注册或要求坚果云、不建立同步身份、不打开发布门禁。云端状态未验证是正常的未启用状态，本地记账与查看可以独立完成。

## 可选：手机与坚果云

本人选择扩展后按[手机与同步](手机与同步.md)操作，沿用现有账本和个人规则。SQLite 仍只在电脑经审核写入。电脑生成展示快照，通过身份绑定、AES-256-GCM 与双槽协议同步；Android 读取认证快照，不直接写 SQLite。

首次同步可能包含已经记入的真实交易展示明细和汇总。先说明范围、取得本次同步授权，再开启原生主门禁与 `.runtime/ledger/publish.json` 本地门禁并刷新；不把这个阶段仍称为“空账本测试”。不会自动把整份 SQLite 或电脑原始 CSV/XLSX 当展示快照上传。

凭据分别在电脑和手机 App 的原生界面输入，每台设备使用自己的坚果云应用密码，并保存到对应设备的安全存储。二维码不传递电脑应用密码，不进入聊天、日志或仓库。每位用户使用独立身份和目录；密码和系统钥匙串授权均由本人处理。

## 可选：手机上传原始账单

### 两条产品线的云端边界

包含目录隔离修复的新版 preview 使用 `Account-Preview/ledger`、
`Account-Preview/probe` 和 `Account-Preview/inbox/身份摘要`；personal 继续
使用原 `Account/` 下相应目录。安装身份决定根目录，显示名称不影响选路。
这使两线可共用云账号，但不代表同一产品线支持多个独立账本共用目录。

旧 preview 云文件保留原处，新版不自动迁移、删除或读取旧根目录。升级保留
本机身份、凭据、配对、缓存及门禁，旧根的发布确认与恢复证据独立留存；
新根须实际发布回读后才算同步成功。电脑与手机需匹配升级，不要求重新配对。
所有目录仍执行原身份认证，非空目录无法认证时拒绝覆盖；合法处置见
[手机与同步](手机与同步.md#云端目录与归属)，不通过放宽归属校验解决冲突。

本人在手机选择上传文件时，原件的加密副本会进入坚果云独立 inbox；电脑校验归档到 `sra/`，经审核入账和数据库核验后才发认证回执。云端可能保留加密文件及历史，因此不能同时承诺“所有原始文件始终只在电脑”。上传、收取、入账、回执分别报告，上传不是入账。

发布需实际云端回读，本机生成文件不代表同步成功。认证或发布失败保留本机账本和上一有效快照，不默认清缓存、重建身份或重新配对。真实设备、同步与原件投递需要本版本实测；未选择或未执行的项目如实标明。
