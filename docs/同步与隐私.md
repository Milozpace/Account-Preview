# 同步与隐私

SQLite 只在电脑经审核写入。电脑生成脱敏快照，通过已有身份绑定、AES-256-GCM 和双槽协议同步；Android 读认证快照，不写 SQLite。协议以原生代码和测试为准，预览适配不更换密码体系或身份模型。

坚果云 WebDAV 凭据分别在电脑和手机 App 原生安全界面输入，每台设备使用自己的应用密码，保存到该设备安全存储。电脑密码不会通过配对二维码传到手机。凭据不进仓库、聊天、日志、命令参数或反馈，二维码仅在用户设备间操作。每位用户建立独立身份、配置和目录，预览 App 不复用生产安全存储。

首次配置顺序为：托管环境和匹配 bundle/helpers → 安装/桌面绑定 → 空库 init/verify → 发布门禁关闭时 refresh 生成本机快照 → `bootstrap.py --apply --initialize-identity` → 用户填写两端凭据并扫码 → 获准后开启双发布门禁 → refresh 上传/回读 → 手机刷新。完整命令见[开始使用](开始使用.md)。SQLite 空库不等于 App 安全身份；初始化命令先检查状态并保留已有身份，不能反复直接调用原生 `--init`。

发布需要原生主门禁和 `.runtime/ledger/publish.json` 的 `enabled` 同时开启。`bootstrap.py --apply --enable-publish` 只幂等设置两道门禁，不上传；随后 `account.py --root ROOT refresh --apply` 才触发快照生成与验证加密发布。用户已授权首次同步时连续执行，无需重复确认；未授权时保持关闭并列待办。

手机原账单经独立加密 inbox 投递，格式/限额以版本提示为准。电脑校验归档、审核入账后才回传认证回执。上传不是入账，回执不替代数据库核验。

发布结果须包括实际云端回读；本机生成文件不是云端成功。认证/发布失败留上一有效快照，不默认清缓存、重建身份或重新配对掩盖问题。

发布前用合成数据和独立测试身份。真实平台、设备、安全存储、配对保持及云端链路须有该版本实测证据，无证据标待验收。
