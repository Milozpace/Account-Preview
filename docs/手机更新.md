# 手机应用内更新

本页说明带“我的 → 关于”版本更新入口的 Android 客户端。首次获得这项功能仍需用现有方式安装一次；旧客户端不会自行出现新入口。公开安装以实际 Release 和设备回执为准。

## 使用方式

1. 打开“我的 → 关于”，在版本信息下点击“检查更新”。新版本会在同页显示版本号、更新内容和下载大小；应用内更新提醒也进入此页。
2. 点击“下载更新”。下载前不自动获取安装包；建议连接 Wi-Fi，移动网络下载会消耗流量。
3. 下载并校验完成后点击“安装更新”。首次可能需要到系统设置开启“允许此来源安装应用”，返回后点“继续安装”。Android 系统安装界面由本人确认。
4. 安装后重新打开应用。安装器被打开只表示已进入系统流程，不代表已经安装成功；取消后可以继续安装。

页面按当前步骤显示检查、下载或安装的主操作；检查及下载期间禁用重复操作。没有更新时显示“已是最新版本”，失败时保留重试入口。安装权限未开启和系统安装器已打开分别提示，不把打开安装器当作更新完成。较长的更新说明默认收起，可按需展开全文；网络要求和校验原理见下文。

应用启动及回到前台会限频检查，自动检查至少间隔 12 小时，网络失败也计入间隔。新版本通过可关闭的应用内提示提醒；“稍后提醒”推迟 24 小时，“忽略此版本”仅关闭该版的自动提醒，手动检查仍可查看和下载。没有后台推送、自动下载或静默安装。没有新版本时继续使用现有程序。

## 网络要求

手机需要通过系统网络访问以下 HTTPS 服务。

| 域名 | 用途 |
| --- | --- |
| `api.github.com` | 查询公开 Release 列表、版本和更新说明 |
| `github.com` | 取得固定 Release 的清单及 Android 组件包 |
| `release-assets.githubusercontent.com`、`objects.githubusercontent.com` | GitHub 官方下载重定向后的资产服务 |

不需要 GitHub 账号或令牌。部分网络可以打开仓库网页，却无法访问 API 或下载资产；仅能访问网页不代表可以更新。应用不内置代理、加速镜像或绕行服务。如果当前网络无法连接这些服务，请切换本人可用网络，或由电脑下载同身份安装包后通过 USB 安装。

GitHub 的匿名接口存在访问频率限制，共享出口也可能受限。接口请求失败时，正式版会尝试从 GitHub 最新正式 Release 的固定清单地址检查；此路径仍需能够访问 GitHub 下载域名，不使用代理或第三方镜像。备用路径未能读取更新说明时会明确提示，可到发布页查看。网络超时、服务不可用或两条路径均无法访问时仍可能失败，稍后重试即可。更新失败不影响已有账单缓存。检查和下载是前台发起的操作，不保证系统杀死应用后继续下载；未完成的包可重新下载，当前不提供断点续传。

账本同步仍通过坚果云。**程序更新与账本同步是两条独立网络通道**：坚果云连接正常不代表 GitHub 可用；更新检查不会读取、上传账本、配对材料或坚果云凭据。

## 工作原理与校验

公开版只查询固定仓库 `Milozpace/Account-Preview` 的已发布正式版本，排除草稿和预发布。选择高于当前产品版本的最新正式版本，并要求 Android 安装序号高于当前设备。

手机下载同版 `release-manifest.json` 和其中指定的 preview / android-arm64 组件 ZIP，沿用已有发布资产。下载地址只接受指定 GitHub 官方 HTTPS 域名，重定向也受同样约束。原生模块校验组件 ZIP 的 SHA-256，核对内部清单的版本、固定提交、平台及安装身份，再检查 APK 哈希、包名、原生版本、安装序号和与已安装应用相同的签名证书。来源信任基于官方 HTTPS Release 与原有应用签名；SHA-256 用来检查文件一致性，并不单独证明发布者身份。

校验通过的 APK 保存在应用专用缓存中，安装前再次核验，通过受限 FileProvider 向系统安装器授予读取权限。系统负责最终安装验证；沿用同一包名和签名进行覆盖升级，不要求卸载、清空数据或重新配对。成功与配对、缓存、偏好保持情况仍以实际设备测试为准。

更新只管理安装包缓存。下载有大小、超时和重定向次数限制；网络、空间或校验失败时不调用安装器，删除未完成的包并允许重新下载。系统清理缓存后需要重新下载。

## 个人版与 USB 备用方式

公开版身份是 `com.account.preview`；个人版是 `com.account.probe`。两者各用原签名，不能互相覆盖。个人包默认只在本机 `personal-local` 交付目录，不上传到公开仓库，本轮个人版入口只说明 USB 更新，不查询或下载公开版安装包。

通过电脑取得与设备对应身份、原签名、适当安装序号的 APK，沿用现有保留数据覆盖安装流程。不要因系统提示不兼容而先卸载旧应用；先核对身份、签名及安装序号。桌面程序、helpers、同版文档及业务衔接仍由 [更新与恢复](更新与恢复.md) 中的电脑更新流程管理，手机 APK 更新不代替电脑项目更新。
