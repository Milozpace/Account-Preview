# 数据与审核契约

Schema 以 `scripts/ledger_store.py` 为准，字段白名单以 `scripts/account.py` 的 `HEADERS` 为准。结构变化同步字典、校验、快照和测试，不手改表绕过工具。

| 表 | 内容/约束 |
|---|---|
| `metadata` | schema/revision 元信息 |
| `ledger` | 身份、序号、唯一键、父/关联 ID、整数分和业务 JSON |
| `budget_rates` | 生效月和四池额度，追加、历史不覆盖 |
| `initial_carry` | 初始滚存，运行/随心为零 |
| `import_batches` | 来源、审核、增改数、修订、前后哈希 |
| `audit_log` | 前后值、原因、确认来源、审核/写入时间，不可覆盖 |

金额用整数分，审核 JSON 可用十进制元文本，空值不补零。订单和关联 ID 为文本。`sourceHash` 是规范化业务、预算、滚存及计算版本的 SHA-256，不是数据库字节哈希；备份不改业务版本。

App V2 新候选的 `coverage.kind=tracked-months` 按本人账本起点连续保留历史，同时兼容旧 `recent-months` 精确两月缓存，见[快照与月份](快照与月份.md)。更新清单的 commit、版本和组件哈希标识发布程序，不替代账本 sourceHash；程序更新不修改本人交易、预算或审核依据。

可选 `local/display.json` 的唯一字段 `trackingStartMonth` 是本人确认的展示起点，不是预算生效月，不改变流水或业务 sourceHash；缓存与导出须另核对该配置对应范围，不能仅凭同一 sourceHash 判断展示最新。配置只在本人本机维护，采用旧个人版时保留其明确设置。

mini 入门的“预算未制定”是 Agent 写入本机档案的状态说明，未新增数据库字段、CLI 模式或 UI 状态。新库仍写完整四池零值以兼容当前初始化；不能把它们解释为本人零元支出上限，也不能仅凭既有零值推断预算未制定。已确认个人消费可保留实际消费金额、直观主分类与待归类资金池；主分类和资金池的待定含义应分别说明。占位政策不适用于任何交易金额。

## 36 个持久字段

| 分组 | 字段 |
|---|---|
| 原始事实（不可按分类改写） | 平台、交易时间、交易对方、商品/说明、原始类型、原始分类、收支方向、原始金额、支付方式、状态、交易订单号、商家订单号 |
| 事件/金额 | 原始财务事件、退款调整、净支出候选、最终财务事件、统计口径、计入消费金额 |
| 分类/解释 | 主分类、细分类、生活领域、服务对象/事件、标签、语义置信度、语义说明、用户修正规则、复核状态 |
| 资金池 | 资金池、资金池判定 |
| 追溯 | 来源行、记录ID、原记录ID、关联记录ID、来源文件、导入批次、记录类型 |

月份/排名由程序派生，不持久存入业务字段。`tx_` 为原交易身份，`alloc_` 派生行须关联原行并校验金额。未知分类留 Unknown/待归类，不虚构置信度。

## 审核 JSON

由 prepare 生成，避免手写原始行或伪造出处。Agent 补 `reviewed_by`、`reviewed_at` 和实际依据，`review_required` 不等于已审定。来源清单含原文件路径与 SHA-256。整批验证行、更新和来源，失败回滚。

首次审核也沿用 prepare 输出的整个 JSON，在其中补充如下信息，不另建缺少来源的简化文件：

| 位置 | Agent 应填写或保留 |
|---|---|
| `reviewed_by` | 实际审定者标识；不得为空 |
| `reviewed_at` | 本次审定时间，使用带时区的 ISO 8601 文本 |
| `reason`、`confirmation_source` | 实际判定理由和证据/用户确认出处；不能编造用户确认 |
| `source_files` | 完整保留 prepare 记录的路径和 SHA-256，不改原件或伪造哈希 |
| `records` 每个新增行 | 明确提供 `最终财务事件`、`统计口径`、`计入消费金额`、`主分类`、`资金池`、`语义说明`；结合规则填写其余派生字段，保留原始 12 字段和 ID |
| `conflicts` | 非空时先定位、解决冲突，不能把冲突改称重复或直接覆盖 |
| `review_required` | 完成实际审核后可标为 false；单改此标志不构成审定，也不授权长期规则 |

字段与事件枚举仍以工具校验为准。先执行不带 `--apply` 的 import，依据准确错误补齐审核，预检通过且本批已获记账授权再执行写入；不得为绕过校验修改原始事实。

`records` 为候选新增，`updates` 显式改派生字段，每项含 `记录ID`、`changes`、`reason`、`confirmation_source`。原始前 12 字段和身份不可更新，规则不得自动覆盖旧确认。冲突须解决，不算成功重复。

快照白名单脱敏，使用整数分与版本；未经契约变更不把订单、账号或完整出处加入展示。
