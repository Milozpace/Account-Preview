# 快照月份与升级兼容

SQLite 是唯一账本，网页 V1 和 App V2 只是统一计算的派生快照。当前候选保留 V1 schemaVersion=1、App schemaVersion=2，加密、身份和双槽不改变。

新导出 App coverage.kind 为 `tracked-months`。SQLite 导出起点取本人最早预算生效月、本人最早交易月与当前月的最小值，从当前月连续降序导出到起点，包含没有交易的空月。未来翻月只增加月份，不滚动删掉历史；新用户不会继承作者的九月起点。未来生效参数的空库至少展示当前月，不虚构旧月份。

Python 与原生校验器要求 coverage.months 与实际 months 完全相符、首月为 calendarMonth、日期合法、无跳月或重复，并继续核对各月净额、分类、四池和明细。接收快照的客户端无法仅凭连续月份证明最早月是否为该用户实际起点；这一点由持有 SQLite 的导出端核对。

已安装旧版仍可能保存 `recent-months` 缓存，该范围继续严格接受本月和上月两个月，保证升级不需清空有效缓存。新源码发现 SQLite 网页缓存缺历史时重新导出；未升级原生 App 不支持新 tracked-months，源码与安装包必须同版交付。0.4.0 已发布包仍保留旧行为，本页新能力须等待 0.4.1 或之后正式发布。

月份菜单保持既有交互，只修复内部焦点转移使鼠标点击选项被提前关闭的问题。所有回归使用虚构数据，不把实际账本或截图作为共享 fixture。
