# 通用记账规则

这是证据、审计与计算底线。个人分类、场景、预算在本机独立维护，不预置任何人的消费习惯。首轮 mini 先整理一个月并可视化，再做简短访谈，预算和详细分类无需在开始前全部制定。

## 事件与净额优先

保留原始平台、时间、对方、说明、方向、金额、状态、订单、出处。先判真实事件及本人最终承担净额，再判口径、分类、资金池。平台“支出”不自动等于个人消费。

| 事件 | 原则 |
|---|---|
| 个人消费 | 按本人最终承担净额，充分证据分类 |
| 退款 | 关联原交易，核对全额/部分、跨期及重复退款，冲减真实承担额 |
| 报销/代垫 | 关联支出与返还，分清本人份额/代付，不只看收入方向 |
| 转账 | 核对双方/用途，资金搬移不重复算消费 |
| 收入 | 保留事实，与消费统计区分 |
| 分摊 | 留原行，派生行关联来源、校验合计，避免双算 |
| 结构性支出 | 有明确口径依据，不扣四池 |
| Unknown / 待归类 | 留待确认事实，不猜分类和预算 |

退款、报销、重复关联不能仅凭金额相等。结合订单/原记录、时间、方向、对方、说明、用户证据；冲突或高影响先询问。跨期调整留来源与理由，统一计算重算。

## 去重与缺失

优先平台与订单身份，ID 用文本保留前导零。缺订单的回退身份只作候选并标复核。相同时间/金额不保证同笔；同身份而原始字段不同形成冲突，禁止覆盖。重复导入无新增、更新或新修订。

空值、占位符、解析失败不是零。证据不足留 Unknown；高影响或反复歧义优先澄清，低影响可合并询问。分类应能说明依据。

## 主分类与分池

主分类回答“钱花在哪类事情上”；资金池回答“这笔支出服务什么用途”。首次导入必须按证据完成两者，分池不依赖是否设额度，也不等访谈结束。可以从少量易懂主分类开始，不要求用户预先设计完整分类体系或采用作者的私人习惯。

以下均为虚构示例，说明通用用途，不构成按商户、金额或主分类自动映射的规则：

| 固定池名 | 用途与例子 |
|---|---|
| 运行账户 | 维持日常生活与通勤，如普通工作日午餐、地铁上班 |
| 随心消费 | 明确的自主娱乐和可选择享受，如周末个人游戏娱乐 |
| 旅行/体验 | 服务于明确旅行或体验事件，如已说明用于某次旅行的住宿和交通 |
| 成长/项目/耐用品 | 学习、明确项目或持续使用的耐用品，如学习课程、项目工具和耐用设备 |

同属餐饮的工作日午餐和旅行途中用餐可能属于不同池，应结合用途证据；仅有商户名、金额或主分类不足以一一映射。本人已确认的个别分配优先保留，不能被通用定义覆盖；退款继承已确认原交易的池，原交易未定时保留关联并澄清。

高影响或反复歧义主动询问；低影响且用途确实不明可说明原因后暂留待归类，保留真实金额。不能整批不分池等预算、猜完所有记录或为覆盖率强填。报告主分类和资金池各自已分配及未完成的笔数与金额、待定原因；全待定不能报分类分池完成。不通过改成非消费或结构性支出来回避预算提示。

## 四池额度与计算（预算可选，分池仍须审核）

| 固定键名 | 默认计算 |
|---|---|
| 运行账户 | 月初重置；月末正结余进独立安全积累 |
| 随心消费 | 月初重置 |
| 旅行/体验 | 正负结余完整滚存 |
| 成长/项目/耐用品 | 正负结余完整滚存 |

上表描述启用预算后的计算。新候选版 init 可不传 amounts，默认四池零额度、零初始滚存，仅在新初始化账本记录 `budgetMode=zero-observation-v1`。首次正数额度生效前为观察期：真实分池消费照常展示，但不产生超支、滚存欠账或安全积累，UI 显示“未设预算”及“设置 → 四池预算”入口。本人明确提供非零初始滚存时也按已启用预算处理。

首次正数额度生效后沿用正常预算机制，包括之后设为零额度的月份；不能把“零”一概当成停用预算。已有未标记账本保留原计算及哈希，不自动推断、迁移或改历史。首次预算可经明确预检确认设在导入月；历史修订走正式设置接口，保留前后额度审计。已有账本和参数不得被默认零值覆盖。

本人以后决定使用预算管理时，再确认四池是否适合、每池额度及场景。额度来自 `budget_rates` 生效月，初始滚存在 `initial_carry`；运行/随心初始值必须零。安全积累不是第五消费池，预算/滚存不是实际现金余额。固定四池不适合时可以继续仅观察记账，不把改名文字当作模型已支持变化。

结构性和待归类不扣四池。后补账、退款、人工确认按证据重算受影响月份，快照不反写。改变计算模型须另明确需求、改代码并回归，不能只改个人文字。

单笔确认只作用该笔。长期学习按[规则与学习](规则与学习.md)批准条件、例外、出处，保护旧确认；规则更新不能无声重判历史。
