# 日常记账 Skill 优化验收

2026-11-03。共享程序、记账 Skill 与配套指引的本地候选，未创建或替换正式 Release。

## 实施结果

- 保留一个 `account-maintenance` 核心 Skill，覆盖手机/本地来源、审核分类与四池、事务入账、核验、结果说明及后续审计纠正。配置、更新仍由原有独立文档负责，AGENTS 只做任务路由。
- 明确用途的消费正常分池；少量、小额且金额/事件已确定的用途歧义可暂留 Unknown/待归类，写具体原因并集中说明。用户补充后用真实 ID 与 updates 修正，不重建原始记录、不额外索取已有操作授权。
- 新增只读 `find-records --month YYYY-MM --query 关键词 --limit 20`，需要月份或关键词，限制 1–100，仅返回定位所需字段，不返回订单号。
- 正式 CLI 新增账单要求保留 prepare 的来源清单。导入前校验哈希、重新解析并绑定原始事实、ID 与来源定位；提交前再次核对哈希。来源文件/行禁止经 updates 绕过，旧库无来源的历史批次仍可核验。
- 回执分开报告 `pending`、`blocked` 与 `receiptErrors`，来源冲突不伪装成成功或网络故障；`classificationReview.reviewComplete` 仅表示本批实际变更的消费是否完成分类分池。
- 更新器随配套发布源码同步官方 Skill 和 references，记录独立内容基线，校验引用完整性，保护其他 Skill 与所有者文档；支持冲突、失败恢复和同版幂等。仅同版 Skill 补齐不重复安装 App。新发布准备拒绝缺少核心 Skill 或引用的源码包。

## 验证

项目托管 Python 执行：

```text
.venv/Scripts/python.exe -X utf8 -m unittest discover -s tests -q
```

结果：366 项，2 项按环境条件跳过，其余通过。新增原始字段遗漏、来源哈希变化、部分入账续接、小额待归类后纠正、定位信息更新绕过、阻塞与网络错误区分、只读 ID 查询、Skill 升级/回退/冲突及发布完整性等回归，均先观察到缺失行为失败，再实现并通过。

以已提供的旧 Agent 实测失败为基线，新 Skill 独立 Agent 场景演练覆盖正常四池、小额待定、后续用户确认、部分入账与回执失败续接。首轮演练发现手机命令顺序及 ID 查询入口不够具体，修订后复测通过。演练是指引应用验证，不冒充 WorkBuddy 实际执行或设备验收。

## 测试部署边界

仅向本人指定的 Preview 测试目录部署明确清单中的共享 Python、官方 Skill 和同版通用指引。覆盖前确认目标文件等于已知官方历史内容，保存原字节及 SQLite Backup API 副本；部署后核对代码、Skill 引用、账本业务哈希、保护文件和只读命令。详细路径、文件哈希及恢复清单仅保存本机 `.runtime`，不提交私人来源或账本。

本轮无原生/前端变更，不重复安装现有 App，不重新配对、修改预算、重判历史、收取真实新账单或发布快照。真实新增账单、云端和手机界面的下一轮实测仍须与本地程序/指引验收分别报告。
