# 公开发布与个人本地版本分离

用户明确调整后续发布规则：公开 Release 只提供公共包；personal 包仅保存在本地。发布 Markdown 只进入 Release 正文，不作为附件。个人版本沿用本人序列，当前 0.3.15，下次 0.3.16，与公开 preview 版本独立。已发布 preview.3 不修改。

- [x] 测试先覆盖公开准备仅需四套 preview 组件、拒绝个人包/Markdown 附件；个人本地包使用独立版本。
- [x] 增加本机 personal 版本配置与构建注入，修改发布准备、公开资产白名单及本地个人更新验证。
- [x] CI 仅构建并上传公共组件；同步 Agent 入口、发布和更新说明。
- [x] 运行相关与全量 Python 测试、版本/隐私检查并复核；提交本轮变更，不发新版本、不安装或改账。

实现边界：公开 release.json 保持公共版本的唯一来源；个人版本配置位于忽略的 local/personal-version.json。个人构建只在显式隔离副本中注入 npm/Cargo/Tauri/Android 版本，原共享 release.json 不改；个人本地索引记录 sourceVersion 与源码 commit，更新器分别校验个人安装版本与共享源码版本。公开索引只列 preview；本地个人索引只列 personal，禁止经远端更新入口发现或下载个人包。

验收：全量 Python 335 项，333 通过、2 跳过；公开版本一致性和 330 个源码文件隐私检查通过。复核补齐个人本地包的采用身份校验，并验证切回公共构建时恢复所有生成版本。CLI 只读演练确认个人下一版本 0.3.16 / 3016；本机忽略配置仍登记当前 0.3.15 / 3015。未构建或安装真实个人候选，未运行新远端 CI、推送或发布；现有 preview.3 保持原样。
