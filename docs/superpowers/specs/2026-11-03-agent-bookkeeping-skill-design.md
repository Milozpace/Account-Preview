# 日常记账 Skill 与版本更新设计

日期：2026-11-03。状态：已按用户最终批准方案实施；验收见 `docs/记账Skill优化验收.md`。

最终范围：只保留核心日常记账 Skill；配置与更新继续各自独立文档，不创建其他 Skill。少量小额用途不明的消费可据实入账并集中说明，用户后续确认通过审计 updates 补正。实施采用独立 `officialSkill` 内容基线，不把个人文档或其他 Skill 纳入管理。

## 目标与行为基准

将个人 Account 已验证好用的 Agent 记账执行方式迁入共享产品。个人版是行为基准，不复制个人账单、身份、预算、商户特例或未经当前使用者批准的规则。首次环境配置继续由文档引导；最高频的日常记账由项目 Skill 提供完整入口，并随所安装的发布版本同步更新。

用户要求：配置通常是一次性的；经典记账流程必须整理为 Skill；程序版本升级时同时取得配套的新 Skill。当前授权覆盖 Preview 中的设计与开发，不包括正式发布、真实记账或修改使用目录的个人规则。

## 已确认的问题

本次只读对照包括个人 Account 指引、共享仓库本机 `v0.4.0-preview.3` 标签和测试使用目录的指引。没有联网认定远端最新版本，也没有访问云端收件箱或运行真实导入。

1. 个人维护 Skill 明确将“记新账单”路由至手机收取、审核、连续入账；Preview Skill 没有手机收件入口，只列 doctor / inspect / prepare 等通用步骤。手机流程藏在工作说明的可选扩展中。
2. Preview AGENTS 与 Skill 都要求先读首次配置指南；初始化、日常记账、预算访谈、开发及发布说明同时出现在入口中，已配置项目也容易重复走入门过程。
3. 个人版明确说明审核者字段记录 Agent 审定，不要求使用者再次批准；Preview 虽允许“帮我记账”授权该批写入，但这条连续执行语义没有集中写在 Skill 中。已检查的指引没有要求每批写入前必须回复“继续”；完整会话与 Agent 宿主约束未取得，不能据此认定样例中的暂停一定违反授权。
4. 通用规则要求按证据完成主分类与分池，规则学习文档仍写“不强求四池分配”；使用目录的历史档案也有相似旧表述。后续不能为消除冲突而覆盖用户明确确认的例外。
5. 审核契约已给出合法字段与审定元信息，但入口未明确按当前契约一次完成，容易反复查历史审核文件来猜格式或审定者名称。
6. 发布源码归档包含 `.agents`，`product_update.managed_name` / `baseline` 只管理程序目录及少量根文件；Skill 只被暂存到 releaseDocs，使用目录里的旧 Skill 不随程序替换。
7. 初始化由 `onboarding._owner_templates` 内嵌文本创建本机档案，并不直接使用 `templates/` 中较完整的档案模板；只修改模板文档不会改变实际生成结果。

不能从展示的总耗时推算提示词、模型推理、文件工具和网络各占多少时间。优化首先消除可观察的重复读取、错误路由与不必要交接，不承诺固定秒数。

## 方案选择

采用“项目内官方 Skill + 已发布版本更新器同步”。它沿用现有 `.agents/skills/account-maintenance/` 名称，避免要求使用者更换 Agent 或维护另一个个人安装副本。

仅将新 Skill 放进版本归档而不更新工作目录，仍会执行旧文件；因此不采用。为不同 Agent 各写一套全局安装器，会增加路径、权限和重复副本维护，本轮也不采用。项目 Skill 通过 AGENTS 明确路由；未自动发现项目 Skill 的 Agent 仍可直接读取该文件。宿主是否支持自动发现、当前会话是否缓存技能另据实际能力报告，不虚报宿主插件已安装或即时热更新。

## 日常入口

AGENTS 开头用简短任务路由区分：日常记账、首次配置、更新、维护者开发。日常记账必须读取官方维护 Skill；环境缺失或异常时才进入配置/故障文档。不能仅因工作记忆或档案缺失就认定没有账本；以实际来源文件、数据库和环境检查为准，不重建已有库。

配置文档保留必要细节；日常入口不要求每次重读整份开始使用、访谈或开发发布规范。通用执行流程以 Skill 为准，用户已确认的私人事实与业务例外继续保留。预算、金额与同步配置以实际拥有它们的程序状态/数据库为准，不从摘要推断。

Skill 的触发描述覆盖：记账、记新账单、手机上传后记账、收取账单、导入账单，以及已入账但回执失败的续接。纯配置和开发不作为记账触发。

## 记账工作流

1. 核对本项目绝对根、项目 Python、账本来源和本次授权；每个会话/环境变更后检查一次环境，正常记账过程中不反复 doctor。环境异常先处理具体问题。
2. 用户明确指定手机上传，或已有启用渠道且本次授权涵盖接收新账单时，先 `inbox-fetch --apply`，再读取本机收件清单取得归档路径。`inbox-status` 不用于判断云端是否有新文件。用户指定本地文件则只处理该范围，按既有归档约定保留原字节及哈希。未授权接收时不擅自连接云端。
3. 对本批已授权且已归档的文件一次调用支持多来源的 prepare；先看候选、重复、冲突与跳过信息，再按需要回查原始内容。不先遍历旧 sra 或旧审核 JSON 猜新来源。
4. Agent 审核：事件与本人净额优先，随后分类与分池。通用规则和使用者已批准规则区分清楚；不照抄个人版的默认商户分类。已有人工确认保留，合法的 Unknown 解释原因，缺金额不补零。审定者填实际 Agent 标识与本次带时区时间，不要求沿用旧批次的人名/格式。
5. 按当前发布版的审核契约一次补齐六个审定字段、来源清单和顶层元信息。非零消费口径使用合法枚举；明确非消费可用 EXCLUDED。历史样例只在确需事实关联时读取，不作为字段契约或新长期规则的替代。
6. 执行 import 预检。有明确该批记账授权、无未解决冲突且操作及既有自动发布均在授权范围时，连续执行 import --apply、verify 和重复预检，不机械增加第二次用户批准。只有授权范围不明、影响事件/净额的歧义、关键冲突或越界发布等实际阻塞才询问。
7. 利用导入的已有后处理完成快照与手机回执；分别读取结果，不重复发布或重新导入。回执失败只重试 inbox-receipts；提交后中断先核对账本证据，不能仅信收到/已记账标志。
8. 普通结果简报实际期间、增改/重复/待确认笔数、净消费/预算影响和核验结果；按启用情况分报展示、云端回读、回执，手机显示仅凭设备实测确认。仅有例外时展开，避免每一步都输出长篇过程消息。

不减少 Backup API、事务审计、来源哈希、去重、幂等与发布授权等实际校验；通过明确路由和批量操作减少往返。

## Skill 与规则的组织

- `SKILL.md`：短而完整的日常执行顺序、触发、授权和恢复分支。
- Skill 内的 `references/`：放精确审核契约和低频恢复细节，按需读取，不把初始化全流程塞入正文。
- 通用业务规则：统一证据、净额与四池用途定义；清除首批分池要求的矛盾，保留真实不明项的处理。
- `local/个人规则.md` 等本机文档：只承载当前使用者已确认的事实、例外与授权出处，不写入共享 Skill，也不把一笔历史审定自动推广为长期规则。
- 初始化生成内容：只提供个人状态记录位置和指向官方 Skill 的稳定入口，不再复制另一套记账流程。缺失文档只补建，不覆盖已有个人文字。

## 配套更新与所有者保护

官方 Skill 采用应用发布版同一固定源码提交，由既有源码 ZIP 的哈希与清单校验覆盖；“最新”指本次所选已发布版本的配套内容，不单独追 main。首次取得完整同版源码即带有 Skill；已有项目升级也同步它的正文及引用文件。

更新器仅增加 `.agents/skills/account-maintenance/` 这一官方目录到受管理范围，不接管其他 Skill、Agent 全局目录、个人档案或私有规则。Skill 文件纳入内容基线、预检冲突、恢复备份、写入后哈希核验及同版幂等；状态/预检/成功结果报告当前 Skill 的绝对路径、版本与同步结果。更新后 Agent 应重读新 Skill，宿主缓存另据能力处理。

新采用基线记录官方 Skill 文件。旧基线未记录 Skill 时：若现有文件等于已核验并暂存的上一安装版本官方文件，允许迁入受管理基线；若与新版本内容完全一致，也可直接纳入。无法证明的既有不同内容视为冲突，保留原文件并明确说明待合并，不用新 adopt 抹掉旧基线或静默覆盖个人扩展。新目录无同名文件时正常安装。

Skill 与应用作为一次更新处理：预检不写，任一 Skill 冲突在安装前停止；失败恢复旧 Skill 和程序并按既有规则报告外部安装状态。缺少配套 Skill 的旧发布包明确报告不含该能力，不声称已经同步；已有较新受管理 Skill 不被旧包删除或降级。正式新发布必须包含必需 Skill 文件及其引用，候选审计验证完整性。

旧使用目录的 AGENTS 与私人文档继续保护，不用更新器整份覆盖。保持原 Skill 路径可使旧入口自然指向新流程；新共享 AGENTS 明确日常路由，更新结果同时给出配套 Skill 入口。不能仅报告 App 安装成功就将整个更新报告为完成。

## 验收

行为演练使用合成场景，不读取真实账单：

1. sra 只有旧文件、手机有新上传：首个来源操作是收取而非继续扫描旧账单；收取完成后使用清单路径 prepare。
2. 已明确授权、已有同步授权且无歧义：审核、预检、入账与核验连续完成，不追加“回复继续”。仅要求看一下时不入账。
3. 纯非消费、首次新审定者：按契约处理，不为审定者格式或合法枚举翻旧批次。
4. 真实用途不明、旧人工确认或自动发布越界：保留证据并按范围询问，不以提速绕过边界，不套个人商户习惯。
5. 提交后回执失败：报告账本成功，走回执重试，不再次导入。

更新器用临时合成项目和发布资产验证：Skill 及引用同步、只读预检、同版无操作、后续版本变化、局部修改冲突、旧基线迁移、缺失旧包、安装失败恢复、引用完整性、路径重定向拒绝；其余个人文件及业务哈希保持。复用既有更新、初始化、发布源码打包相关回归。

将演练与实际宿主/设备测试分开报告；未在 WorkBuddy 真实运行的模型表现或速度不宣称已验收。

## 实施范围

预计修改官方维护 Skill 及引用、AGENTS、工作/规则/初始化与更新说明、onboarding 模板生成、product_update 的官方 Skill 管理、发布包完整性检查及相关合成测试。先在功能分支验证后提交。保持 App 版本号、发布标签、真实账本、个人规则、安装身份、配对与云端状态不变；不自动发布或安装未发布候选。
