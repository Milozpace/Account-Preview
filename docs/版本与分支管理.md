# 版本与分支管理

2026-11-07 起，Account-Preview 的 `dev` 是唯一共享开发主线。个人和公开独立编号、构建、验收和交付，共享源码通过完整提交追溯。此前统一产品版本的约定由本文取代，既有标签、资产和回执保留。

## 分支职责

| 分支 | 基线 | 职责与合入方向 |
|---|---|---|
| `main` | 已验证的公开交付及经批准的文档修订 | 程序来源推进到实际公开交付的源码。文档可独立修订，公开安装仍取固定 tag/Release。 |
| `dev` | 当前共享开发基线 | 集成共享功能、修复及工具。个人与公开交付均从已验证的共享源码选定提交。 |
| `feature/<事项>`、`fix/<事项>`、`codex/<事项>` | `dev` | 短期开发和验证，完成后合回 `dev`。 |
| `release/<系列或版本>` | 拟交付的 `dev` 固定提交 | 按需冻结公开候选。通过发布验收后推进 `main`，版本文件及适用修复回流 `dev`。 |
| `codex/personal-<版本>` 或隔离工作树 | 已验证的共享固定提交 | 固定本地个人交付来源。后续共享开发回到 `dev`，交付分支保留作溯源。 |
| `hotfix/<事项>` | 受影响的已发布 tag 或维护线 | 聚焦对应旧版修复，按发布流程交付，并将适用修复回流 `dev`。 |

已有分叉先核对提交关系和内容差异，合并时保留两边适用行为，验证后合回 `dev`。短期移植需记录原提交和新提交，避免把已有功能重复搬运。历史分支保留，禁止批量改写历史。开始前核对工作区、远端、目标分支及未提交改动。在独立源码工作树构建和测试，保留使用目录和私人文件。

## 版本与交付记录

| 信息 | 公开 preview | 本地 personal |
|---|---|---|
| 交付版本输入 | `release.json`，用 `scripts/product_version.py` 生成对应 npm、Cargo、Tauri 和 Android 元数据 | 本机忽略的 `local/personal-version.json`，用 `scripts/personal_version.py` 核对版本与 Android 安装序号 |
| 交付依据 | `v<版本>` tag、Release、索引与组件哈希 | `personal-local` 索引、固定源码、组件哈希与安装回执，留在本机 |
| 安装身份 | `com.account.preview`、`AccountPreview`、对应签名和云命名空间 | `com.account.probe`、`AccountDesktop`、原个人签名和云命名空间 |

两种交付可取同一提交，也可按各自节奏取不同的已验证提交。个人清单的 `version` 是个人交付版本，`sourceVersion` 来自固定源码的 `release.json`，完整 commit 区分同一源码版本字段下的不同开发提交。原生版本和 Android 安装序号按身份分别核对已交付及实际已安装下限，新交付均须递增。快照 schema、云 revision 与业务 sourceHash 继续描述各自的契约或数据状态。

普通开发、实验和文档提交用 SHA 区分。隔离环境的本地测试构建用 SHA、构建标识与哈希记录。真正交付时才定号，公开系列或渠道变化须经维护者确认。已交付版本的源码关联和资产固定，修订后分配新版本。版本比较采用 [SemVer 2.0.0](https://semver.org/lang/zh-CN/spec/v2.0.0.html)。兼容修复通常递增 patch，兼容功能通常递增 minor，同一目标的预发布交付递增相应序列。0.x 的契约变化另行核对迁移和兼容窗口。避免在测试设备上提前消耗后续正式覆盖安装需要的安装序号。

## 发布与安装

- 公开发布先验证固定提交、安装号下限、三平台候选、升级路径与说明。每版经维护者明确确认后，使用同一提交创建 tag 和 Release。CI 仅验证并产候选，按已授权范围推送。
- 公开更新发现按实际执行更新器的能力验证。历史频道 `private-preview` 沿用。preview.5 自动发现仅支持 preview 标签，首次升级到 rc.1 走已发布资产的本地目录。rc.1 更新器支持最新 preview 系列内的后续 RC。启用其他系列或渠道时单独验收发现与升级路径。
- 个人构建、组件打包和索引准备都绑定同一份个人版本配置与完整提交。安装使用获准的本地交付目录，核对身份、原签名、哈希和实际安装下限。构建命令见[开发、同步与发布规范](开发同步与发布规范.md)。
- 区分提交、合入、CI、制品、安装和公开发布。交接记录产品版本、源码版本和完整提交、profile、平台、原生版本、Android code、组件哈希、实际验证及各端安装结果。设备状态查对应回执，公开状态查远端 tag/Release。

开始新任务先读 `AGENTS.md`、[开发状态与交接](开发状态与交接.md)及对应契约。收尾时更新共享交接状态并精确提交本次文件。个人制品和设备回执的本机路径留在忽略的 `local/开发环境.md`。
