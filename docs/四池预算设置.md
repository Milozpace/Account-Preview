# 四池预算设置

先导入本人选择的账单，实际消费、日历、分类和明细即可查看。累计图统计全部本人净消费（含退款和未分池记录），与是否已经制定预算无关。新初始化账本默认四池零额度与零滚存，采用 `zero-observation-v1` 观察模式：显示“未设预算”，可从“设置 → 四池预算”填写额度。这不是零元支出上限；首批仍须按用途证据完成主分类和分池。

观察期实际分池消费可见，但不产生超支、滚存欠账或安全积累。首次正数额度生效的月份开始正常预算计算；若本人明确提供非零初始滚存，也按预算已启用处理。启用后即使后续额度降为零，仍继续计算消费、超支、滚存及适用的安全积累，不因零额度重新进入观察期。已有未标记账本保留原计算与业务哈希，不仅凭零值推断观察状态，不自动迁移或重算历史。

## 在电脑上调整

打开“应用设置 → 四池预算”。选择已有生效月或填写新增月份，填写四池每月额度和修改理由，点击“预览更改”。页面显示新旧额度以及影响区间，核对后再“确认保存”。首次额度可以选择导入账单的月份，不必等到下月；也可继续观察，暂不设额度。

每条额度从生效月沿用至下一条生效月之前。修订历史额度会重算该区间预算以及可能延续到后续月份的滚存/安全积累，不修改交易事实、分类、ID或来源。预览中的区间指本条额度直接适用月份，不代表后续滚存一定不受影响。历史修改应如实说明是回顾性参考，不能伪称消费发生前已有约束。

“重新读取”可取得最新账本哈希，保留尚未保存的输入并清除旧预览。账本变化后旧预览不可保存，需要重新预览。保存前自动保留恢复副本，事务写入额度并记录前后值、理由及本人确认依据；失败整体回滚。相同有效参数重复保存不增加修订。

额度保存只生成本地快照，不自动云端发布。若提示“额度已保存，展示未更新”，先重新读取确认额度，再处理本地展示；不要为了刷新反复修改额度。同步身份、配对及发布门禁保持。

预算与分池不同：填写额度不会替未分池记录猜用途；未设预算也不构成跳过首次分池的理由。Agent 按[通用用途定义](记账规则.md#主分类与分池)审核，实际歧义说明后待确认，保留本人已确认的个别分配。历史补分类或分池另按授权处理，不随额度修改自动重判。

## Agent 使用正式工具

额度保存在 SQLite 的 `budget_rates`，不是源码或另一个预算 JSON。JSON 只用作本次输入；不编辑前端/Python 常量或直接 SQL。读取和预检不写数据：

```text
PY ROOT/scripts/app_desktop.py budget-status --project-root ROOT
PY ROOT/scripts/account.py --root ROOT budget-set --effective YYYY-MM --amounts 本机四池额度.json --expected-hash 当前sourceHash --reason 本人确认依据
PY ROOT/scripts/account.py --root ROOT budget-set --effective YYYY-MM --amounts 本机四池额度.json --expected-hash 当前sourceHash --reason 本人确认依据 --apply
```

金额 JSON 必须有四个准确的池名、非负的两位小数文本，例如使用通用模板的四个键。`--expected-hash` 必须来自本次读取，不能写死；收到过期提示后重新读取。常规 `budget` 命令仍保留只追加的保护；`budget-set` 专门承载明确修订，不代表普通记账获得调整预算授权。

普通使用者的 Agent 负责配置、通过已发布版本拉取覆盖程序、使用正式命令记账并维护个人规则。产品缺陷报告给维护者，避免在使用目录临时修改共享源码。电脑版新增设置延续左侧分类与右侧分组行；手机仍以查看与投递为主，不直接改 SQLite。
