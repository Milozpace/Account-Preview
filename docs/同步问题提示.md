# 同步问题提示契约

本契约用于0.4.0 及后续兼容版本的 App。它不改变账单 schema、安装身份、加密双槽或云端路径。旧 App 不会自动获得新的错误文案，首次升级按[更新与恢复](更新与恢复.md)执行。

## 原生与界面

`ledger_fetch`、`ledger_import_pairing`、`sync_configure` 的 Tauri 失败结果为结构化问题：`code`（稳定错误类型）、`stage`（发生阶段）、`message`（脱敏详情）、可选 `httpStatus`、`retryable`。凭据、URL、配对材料和响应正文不进入这些详情。内部命令行继续保留字符串兼容接口。

获取到一个有效槽位、另一个检查失败时，成功结果保留旧 `warning`，同时可带 `issue`。界面明确未完全确认云端最新状态；不能将部分成功显示为完整同步成功。若另一槽是通过配对认证、版本更高或相同的不可读快照，拒绝退回旧槽冒充最新，保留有效缓存。

| 类型 | 主要代码 | 用户操作 |
| --- | --- | --- |
| 认证拒绝 | `auth-unauthorized` | 核对坚果云账号和应用密码 |
| 权限拒绝 | `access-forbidden` | 核对账号、第三方应用权限和服务状态，不断言密码错误 |
| 路径异常 | `cloud-path-missing`、`cloud-path-conflict`、`cloud-directory-invalid` | 按阶段检查服务地址或电脑同步目录；409 不证明密码错误或未发布 |
| 临时失败 | `request-timeout`、`network-unavailable`、`rate-limited`、`service-unavailable` | 依据网络、限流或服务提示重试 |
| 新数据格式 | `snapshot-newer-schema` | 手机更新到支持该契约的版本后再获取 |
| 已验证旧数据格式 | `snapshot-older-schema` | 电脑更新并重新生成、发布快照 |
| 数据安全与版本冲突 | `snapshot-invalid`、`snapshot-authentication-failed`、`snapshot-revision-conflict`、`snapshot-rollback` | 保留有效缓存，让电脑 Agent 检查配对、完整性或发布记录 |
| 配对失败 | `pairing-invalid`、`pairing-unsupported`、`pairing-authentication-failed`、`pairing-foreign-identity` | 重新确认二维码来源与版本，不覆盖原配对 |
| 本机或配置问题 | `local-state-unavailable`、`configuration-invalid`、`configuration-foreign-account`、`sync-not-configured` | 检查对应本机授权、配置或账号；不清空应用数据 |

界面为“待完成 / 需要留意 / 需要处理”三种程度，显示原因、建议操作和缓存影响，详情折叠保留阶段、代码与 HTTP 状态。旧原生字符串仅在有明确状态或内容证据时分类；“认证/契约/版本检查”阶段名不构成密码错误证据。旧 `401/403` 合并描述不强行归为 401，有单独 HTTP 状态时优先使用该状态。未知错误保留详情，不能统一归为密码或版本问题。

## 凭据与首次同步

候选凭据使用服务根目录 Depth 0 PROPFIND 只读验证，确认 DAV collection 后才保存。认证、服务检查、保存或保存后状态读取失败时保留或恢复旧凭据；验证不建立目录、不发送 probe、不发布账单。已有配置状态仍只代表本机保存过配置，不是长期有效的云端认证凭证。

两个槽位都不存在时返回 `cloud-empty`，这是等待获取账单的正常状态。显示电脑首次同步指引，同时提醒已发布者核对两端账号；不能仅凭空目录证明电脑从未发布。首次同步收尾须核对用户授权、两道门禁、实际发布及云端回读、手机获取，见[手机与同步](手机与同步.md)。

变更原生实现时，App 与同一 crate 的 helpers 必须同轮构建、按固定来源交付。测试使用合成账本、隔离安全存储和回环 HTTP 服务，不对真实云端故障注入。
