# 让 Agent 更新已发布版本

完整更新包含程序覆盖、同版文档重读及适用的[版本衔接事项](版本衔接指引.md)。先读远端最新更新入口，再按目标已发布 Release 的固定源码执行；不要在使用目录直接 git pull 或用开发分支覆盖。Agent 更新后须实际重读 `releaseDocs` 中的本文件、累计版本衔接指引及已同步的官方记账 Skill／references；聊天缓存不会自动更新。跨版逐项检查尚未完成事项，软件已安装不等于业务衔接已完成。旧版无指引时明确报告。

preview.5 首次加入收入的历史分类复核：默认最近三个自然月，短历史全部；历史跨度超过三个月先让本人选三个月、六个月、其他范围或全部。使用只读 `income-review-candidates` 定向查询，再由 Agent 按审计流程纠正，不能按关键词自动改账。详见同版累计指引；更新器自身继续不修改账本。程序、文档、收入复核、快照／云端与设备分别验收。

从 preview.5 起停止 Intel Mac App、Python 引导与 CI 支持，macOS 仅支持 Apple Silicon；历史 Release 保留。

对 Agent 说“帮我更新到最新已发布的试用版，保留我的数据和配置”。这里更新的是项目程序、对应 App 和辅助工具，不重新建库、不重新配对、不发布账本快照，也不将开发分支当作发布版本。

公共用户以实际已发布 Release 为准。历史 preview.2/3 曾附 personal 包，后续公开 Release 只提供 preview 公共包；personal 保留原身份，使用本地交付目录，不能用 preview 包替换。个人开发版和公开发布版分别编号并记录来源提交；旧个人独立索引与旧统一索引仍按原格式兼容，不能重写旧回执。版本与身份规则见[版本与分支管理](版本与分支管理.md)。旧版首次由 Agent 在独立工具目录准备更新工具，不先覆盖使用目录或切换 Git 历史。

## 1. 只检查并采用本机身份

先选择产品工具源码所在目录 `TOOLS`、本人账本根 `ROOT` 和执行工具的 Python `PY`，全部用绝对路径并引用空格。两个目录可以相同；个人 Account 可从旁边 Preview 工具目录执行，真实账本仍留在 ROOT。

```text
PY TOOLS/scripts/product_update.py --root ROOT status
PY TOOLS/scripts/product_update.py --root ROOT adopt --profile personal
PY TOOLS/scripts/product_update.py --root ROOT adopt --profile personal --apply
```

新用户/朋友将 `personal` 换成 `preview`。既有项目不猜身份，也不能覆盖既有状态更换 profile。采用操作核验账本并记录程序内容基线，写 `.runtime/product/state.json`；若个人旧版已有明确展示起点常量，还会只读解析并保存到本人 `local/display.json`，不执行旧代码或继承作者设置。已有本地配置不覆盖，已有程序基线不重置；旧工具已登记而尚未迁移该设置时，可同身份再次 adopt 续接。不会安装或修改交易、预算、凭据。个人版是 com.account.probe，朋友版是 com.account.preview；包互不替换。

已有新工具的项目也可使用统一入口：

```text
PY scripts/account.py --root ROOT update-status
PY scripts/account.py --root ROOT adopt-product --profile preview --apply
PY scripts/account.py --root ROOT update
```

这些命令里的 ROOT 仍为本人根；不因为工具在别处就改账本来源。本机未采用前，确认没有进行中的开发修改，再建立基线；基线不是“这些任意本机文件都适合公开”的批准。

## 2. 检查最新已发布试用版

本节远端入口供 preview 使用。personal 远端检查会在请求网络前停止并提示本地目录；个人预检使用 `PY TOOLS/scripts/product_update.py --root ROOT check --release-dir 本地个人版本目录`，更新时使用 `update --release-dir 同一目录 --prepare-python --apply`。该目录须含 `distribution: personal-local` 的索引、匹配身份的组件和绑定固定提交的共享源码包；个人交付版本与源码版本独立记录并分别校验，旧统一索引按其原格式核验。不更改私人预算、规则或配对。

```text
PY TOOLS/scripts/product_update.py --root ROOT check
```

工具按实际版本数字比较已发布的 `X.Y.Z-preview.N` 标签，并接受最新 preview 产品系列的 `X.Y.Z-rc.N`；排除草稿，不使用会遗漏 prerelease 的 latest 接口。preview.5 自带的旧更新器无法自动发现 RC，首次升级路径见[版本衔接指引](版本衔接指引.md)。仓库已公开，工具可匿名读取和下载，不要求 gh 安装或登录。访问失败先检查网络或请求限额；若实际改回受限才处理本人权限，不把密码或令牌贴进聊天。

依次校验发布索引、同版源码、原生组件的 SHA-256、固定源码提交、平台、安装身份及账本/快照 schema；发布目录须有 `release-manifest.json`。不兼容就停止，不猜测/跳过校验，也不自动迁移数据库。资产解压不得出现路径跳转、重复或大小写别名、链接和个人目录。

本地程序偏离采用基线时，先保留并处理源码冲突；不使用 git reset/clean、强制 pull 或重新 adopt 抹掉基线。个人原件、个人规则、所有者文档及源数据配置不作为共享程序覆盖。当前通用说明归档在工具返回的 `releaseDocs`（`.runtime/product/releases/版本/source`）中，Agent 更新后读取该版说明，并继续尊重本人的已有确认。

个人本地升级仍须高于已安装的原生版本和 Android versionCode，包括旧 0.3.x 以及历史公开 personal preview 包。核对真实设备及历史回执，使用个人配置生成更高的安装序号，不只改索引或清掉旧版本配置绕过保护。

### 官方日常 Skill 随版同步

独立版本的 `personal-local` 交付保留本机已有的个人记账 Skill 及其引用目录，预检和更新后都核对本机内容。回执的 `officialSkill.state` 为 `owner-managed`，记账仍从本机入口开始。发布 Skill 及其引用照常通过发布源码校验，随同版源码存档，供单独查阅。Preview 安装继续按下文规则同步发布 Skill。

更新器只管理 `.agents/skills/account-maintenance/SKILL.md` 及其 `references/` 必需文件，不把整个 `.agents` 纳入覆盖。它们来自本次已校验的固定提交源码包，与程序版本匹配；引用缺失或本地官方文件偏离已记录基线时停止并报告冲突，不盲覆盖。`AGENTS.md`、本机记忆、档案、个人规则及其他 Skill 仍受保护；通用文档在 `releaseDocs`，旧所有者文档中的流程不能反向覆盖同版官方 Skill 或本人确认。

检查和更新结果的 `officialSkill` 报告入口路径、`version`、`sourceVersion`、`commit` 与状态。`synchronized` 表示本地字节匹配已记录来源；`pending` 表示预检待同步；`modified`/冲突须保留本地修改核对；`untracked` 表示尚无受管基线；`unsupported` 表示目标旧包没有官方 Skill，保留旧文件但不能声称它与该程序匹配。

已安装同一发布版仍可重复执行原更新预检/`--apply`，补齐同版缺失/旧管理状态的官方 Skill；清单与程序哈希仍须一致，不能用 main 文件补丁冒充已发布版本。若没有受信任旧来源基线且本地文件不同，先报告冲突；不借重新 adopt 绕过。仅补齐 Skill 不重复安装同版 App。更新后 Agent 必须重新读取实际入口和所需 references，已有聊天/工具缓存不会因磁盘文件更新自动刷新；日常工作按新入口继续，不能只宣布文件已更新。

## 3. 获准升级后执行

```text
PY TOOLS/scripts/product_update.py --root ROOT update --apply
```

用户已经要求更新且预检通过时连续执行，不额外重复询问。需要新建 Python 环境，或 requirements.lock/pyproject 变化时，须带 `--prepare-python`。必须从目标 `.venv` 之外的 Python 启动，避免 Windows 更新正在运行的解释器：

```text
PY TOOLS/scripts/product_update.py --root ROOT update --prepare-python --apply
```

Agent 可使用 TOOLS 已准备的 uv 托管 Python 执行，普通用户不安装开发链。缺托管 uv 时按入门流程在独立工具目录准备；不得依赖 Agent 内置 Python 作为长期项目解释器。更新器准备 ROOT 专用环境，并将对应安装身份的桌面绑定指向它。已有绑定属于另一用户根时拒绝覆盖。

执行前使用 SQLite Backup API 保存恢复副本，暂存已验证源码与安装包，记录旧程序和配置。代码与 helpers 按版本匹配，保留旧版供恢复；旧发布门禁保持启用/关闭原值，只在存在显式 publisher 路径时更新为同身份新 helper。升级不调用 refresh、云端发布、收件或回执。

更新后核验账本业务哈希及个人保护文件、桌面绑定和安装结果。App 启动/实际页面、云端和手机验证分别报告；命令完成不自动等于所有设备实测通过。Android 是可选步骤，按原 profile 取得对应已签名 APK，保持原签名覆盖安装，设备未连接标未执行。

离线演练使用 `--release-dir 本机发布目录`，目录必须含完整清单、源码 ZIP 及当前 profile/平台 ZIP；校验规则不降低。每次检查默认不写入本人目录；重复同版且内容一致时不重复安装。

## 4. 失败与中断

源码/哈希/权限/冲突问题先修具体问题，保留数据和已验证旧包。安装失败会尝试恢复程序、helpers 清单和工具改过的配置，但外部安装器可能已部分改变 App，结果会标“安装状态待核对”，不声称二进制完全回滚。Python 依赖准备失败也须修复环境，不能假装已回退。

`.runtime/product/recovery/` 保留日志、先前程序和 SQLite 副本；update.lock 或 pending 指向未完成操作时先检查恢复记录，不删锁硬跑。进程已结束而 pending 仍在时，由 Agent 根据 journal 核对哪些文件已切换、恢复程序或完成同版更新并核验后处理标记；不可随意恢复旧账本而丢掉后续已记账数据。

回退 App 须确认数据库/协议兼容。恢复数据库仅创建全新候选，另获替换来源授权后才能切换；更新失败不自动倒退业务账本。不清空整个 `.runtime`，不卸载并删除数据、不重置安全存储。
