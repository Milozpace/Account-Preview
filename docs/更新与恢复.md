# 让 Agent 更新已发布版本

对 Agent 说“帮我更新到最新已发布的试用版，保留我的数据和配置”。这里更新的是项目程序、对应 App 和辅助工具，不重新建库、不重新配对、不发布账本快照，也不将开发分支当作发布版本。

默认分支当前为未发布的 `0.4.1-preview.1`。已发布 `0.4.0-preview.1` 没有新版更新清单或 personal 包；更新器会解释缺项并停止，不能把它装到现有个人版上。新更新流程须等维护者填写说明、批准并发布包含清单的新版本后实际升级。旧版用户首次可由 Agent 在独立工具目录取得新版工具源码；不要先覆盖使用目录或切换其 Git 历史。

## 1. 只检查并采用本机身份

先选择产品工具源码所在目录 `TOOLS`、本人账本根 `ROOT` 和执行工具的 Python `PY`，全部用绝对路径并引用空格。两个目录可以相同；个人 Account 可从旁边 Preview 工具目录执行，真实账本仍留在 ROOT。

```text
PY TOOLS/scripts/product_update.py --root ROOT status
PY TOOLS/scripts/product_update.py --root ROOT adopt --profile personal
PY TOOLS/scripts/product_update.py --root ROOT adopt --profile personal --apply
```

新用户/朋友将 `personal` 换成 `preview`。既有项目不猜身份，也不能覆盖既有状态更换 profile。采用操作核验账本并记录程序内容基线，仅写 `.runtime/product/state.json`；不安装、不修改交易或凭据。已有状态则幂等保留。个人版是 com.account.probe，朋友版是 com.account.preview；包互不替换。

已有新工具的项目也可使用统一入口：

```text
PY scripts/account.py --root ROOT update-status
PY scripts/account.py --root ROOT adopt-product --profile preview --apply
PY scripts/account.py --root ROOT update
```

这些命令里的 ROOT 仍为本人根；不因为工具在别处就改账本来源。本机未采用前，确认没有进行中的开发修改，再建立基线；基线不是“这些任意本机文件都适合公开”的批准。

## 2. 检查最新已发布试用版

```text
PY TOOLS/scripts/product_update.py --root ROOT check
```

工具按实际版本数字比较已发布的 `X.Y.Z-preview.N` 标签，包含预发布版、排除草稿，不使用会遗漏 prerelease 的 latest 接口。私有仓库使用本人已有 gh 登录态；将来公开后可匿名读取。访问失败时在本机处理权限，不把密码或令牌贴进聊天。

依次校验发布索引、同版源码、原生组件的 SHA-256、固定源码提交、平台、安装身份及账本/快照 schema；发布目录须有 `release-manifest.json`。不兼容就停止，不猜测/跳过校验，也不自动迁移数据库。资产解压不得出现路径跳转、重复或大小写别名、链接和个人目录。

本地程序偏离采用基线时，先保留并处理源码冲突；不使用 git reset/clean、强制 pull 或重新 adopt 抹掉基线。个人原件、个人规则、所有者文档及源数据配置不作为共享程序覆盖。当前通用说明归档在工具返回的 `releaseDocs`（`.runtime/product/releases/版本/source`）中，Agent 更新后读取该版说明，并继续尊重本人的已有确认。

## 3. 获准升级后执行

```text
PY TOOLS/scripts/product_update.py --root ROOT update --apply
```

用户已经要求更新且预检通过时连续执行，不额外重复询问。需要新建 Python 环境，或 requirements.lock/pyproject 变化时，须带 `--prepare-python`。必须从目标 `.venv` 之外的 Python 启动，避免 Windows 更新正在运行的解释器：

```text
PY TOOLS/scripts/product_update.py --root ROOT update --prepare-python --apply
```

Agent 可使用 TOOLS 已准备的 uv 托管 Python 执行，普通用户不安装开发链。缺托管 uv 时按入门流程在独立工具目录准备；不得依赖 Agent 内置 Python 作为长期项目解释器。更新器准备 ROOT 专用环境，并将对应安装身份的桌面绑定指向它。已有绑定属于另一用户根时拒绝覆盖。

执行前使用 SQLite Backup API 保存恢复副本，暂存已验证源码与安装包，记录旧程序和配置。代码与 helpers 按版本匹配，保留旧版供恢复；旧发布门禁保持启用/关闭原值，只在存在显式 publisher 路径时更新为同身份新 helper。升级不调用 refresh、云端发布、收件或回执。

更新后核验账本业务哈希及个人保护文件、桌面绑定和安装结果。App 启动/实际页面、云端和手机验证分别报告；命令完成不自动等于所有设备实测通过。Android 是可选步骤，按原 profile 取得对应已签名 APK，保持原签名覆盖安装，设备未连接标未执行。

离线演练使用 `--release-dir 本机发布目录`，目录必须含完整清单、源码 ZIP 及当前 profile/平台 ZIP；校验规则不降低。每次检查默认不写入本人目录；重复同版且内容一致时不重复安装。

## 4. 失败与中断

源码/哈希/权限/冲突问题先修具体问题，保留数据和已验证旧包。安装失败会尝试恢复程序、helpers 清单和工具改过的配置，但外部安装器可能已部分改变 App，结果会标“安装状态待核对”，不声称二进制完全回滚。Python 依赖准备失败也须修复环境，不能假装已回退。

`.runtime/product/recovery/` 保留日志、先前程序和 SQLite 副本；update.lock 或 pending 指向未完成操作时先检查恢复记录，不删锁硬跑。进程已结束而 pending 仍在时，由 Agent 根据 journal 核对哪些文件已切换、恢复程序或完成同版更新并核验后处理标记；不可随意恢复旧账本而丢掉后续已记账数据。

回退 App 须确认数据库/协议兼容。恢复数据库仅创建全新候选，另获替换来源授权后才能切换；更新失败不自动倒退业务账本。不清空整个 `.runtime`，不卸载并删除数据、不重置安全存储。
