# 更新与恢复

本页供 Agent 更新已有安装和处理升级失败。首次安装见[开始使用](开始使用.md)，日常入账失败见记账 Skill 的[恢复说明](../.agents/skills/account-maintenance/references/recovery.md)。

完整更新要核对程序、App/helpers、适用文档/Skill 和跨版本事项。用户已授权本次升级且预检通过时连续执行，真实改账、云端发布及设备操作按本次实际授权处理。

## 1. 确认目录、身份和执行工具

| 名称 | 含义 |
| --- | --- |
| ROOT | 本人的使用目录，保存现有 SQLite、原件与配置 |
| TOOLS | 执行更新器的已核验工具源码目录，可与 ROOT 相同 |
| UPY | 用于启动更新器的 Python，准备 ROOT 环境时必须位于 ROOT/.venv 之外 |
| DELIVERY | 已核验的本地发布目录，用于首次 RC 或 personal 交付 |

以下命令是模板，Agent 替换为绝对路径，按当前 shell 引用。日常记账继续使用 ROOT 自己的项目 Python。

先只读查看状态。

```text
UPY TOOLS/scripts/product_update.py --root ROOT status
```

检查 adopted、profile、version、releaseDocs、pending 和 updateLocked。有中断标记时先进入[失败与中断](#失败与中断)。

| 使用身份 | 取得目标的方式 |
| --- | --- |
| preview，标识 com.account.preview | 已发布的公开 Release |
| personal，标识 com.account.probe | 本人获准的 personal-local 本地交付目录 |

未采用时，先核对实际安装身份、源码修改和账本状态，再建立更新基线。以 preview 为例，personal 替换 profile。

```text
UPY TOOLS/scripts/product_update.py --root ROOT adopt --profile preview
UPY TOOLS/scripts/product_update.py --root ROOT adopt --profile preview --apply
```

adopt 记录程序基线和身份，已有基线继续保留。旧个人版明确的展示起点常量可被只读解析并保存到本机 `local/display.json`，已有设置优先。冲突按真实来源处理。

## 2. 先取得目标版本的流程说明

默认分支的更新文档用于发现入口。具体操作以**目标固定源码**内的同版《更新与恢复》和 Release 说明为准。必要时先在独立工具目录下载、校验并解压该版源码，读取文档，再执行更新。

已安装版本的通用文档位于 status 返回的 releaseDocs。使用根的 docs、AGENTS、PROJECT_MEMORY 和个人档案按所有者材料保护，更新后可能保留原文字。

预检报告的目标 releaseDocs 是将来归档位置，预检阶段该目录可能尚不存在。更新前从已校验的目标源码包读取，更新成功后再从实际 releaseDocs 重读。

| 能力 | 核对方式 |
| --- | --- |
| 自动发现 RC | preview.5 自带工具仅发现 preview，首次 RC 用本地目录；rc.1 支持同系列后续 RC |
| 收入快照 | preview.5/rc.1 为 Web 2、App 3；旧客户端按[快照与月份](快照与月份.md)协调升级 |
| personal 的 local-only Skill 策略 | 属于 rc.1 后的共享开发能力，须确认实际执行工具支持，再使用省略 Skill 的包 |
| updateDoc、changedDocs、signing 报告 | 属于 rc.1 后的共享开发能力，旧更新器可能没有这些字段 |

版本发现、索引支持与设备安装下限由正在执行的工具决定。某字段缺失或无法比较时，按实际固定源码和发布说明核对。

## 3. 检查目标并预检

Preview 的常规检查如下。

```text
UPY TOOLS/scripts/product_update.py --root ROOT check
```

工具读取实际 Release 列表并筛除草稿，按其支持的 preview/RC 序列选择目标。公开下载可匿名进行。网络失败先核对实际请求错误。

preview.5 首次升级 RC，或使用 personal-local 时，将对应目录交给更新器。

```text
UPY TOOLS/scripts/product_update.py --root ROOT check --release-dir DELIVERY
```

DELIVERY 至少包含完整 release-manifest.json、同版源码 ZIP、当前身份/桌面平台的组件 ZIP。个人目录须为 personal-local，保留独立个人版本、sourceVersion 和完整提交。旧格式索引按其原契约核验。

预检会读取、下载或在临时目录校验资产，默认不改本人使用目录。须检查来源提交、哈希、平台、身份、schema、安装序号、程序/Skill 基线与环境要求。遇到冲突先处理，再以同一目标重跑预检。

能返回这些字段的工具，按下表解释。

| 报告 | Agent 应做什么 |
| --- | --- |
| requiresEnvironment | 为 true 时使用外部 UPY，并在执行阶段加 prepare-python |
| officialSkill | 区分 preview 随版管理与 personal 所有者管理，处理真实冲突 |
| updateDoc.changed | 为 true 时先读目标更新流程，null 表示缺比较基线 |
| changedDocs | 重读列出的变化文档，缺历史基线时另核对固定源码 |
| signing | 记录构建方提供的信息与变化，未提供时说明未知 |

## 4. 按已授权范围执行

预检通过后，使用相同 TOOLS、身份和目标执行。常规远端更新如下。

```text
UPY TOOLS/scripts/product_update.py --root ROOT update --apply
```

需要准备环境时，UPY 必须位于 ROOT/.venv 之外，避免 Windows 覆盖正在运行的解释器。

```text
UPY TOOLS/scripts/product_update.py --root ROOT update --prepare-python --apply
```

本地目录更新如下，准备环境的条件相同。

```text
UPY TOOLS/scripts/product_update.py --root ROOT update --release-dir DELIVERY --prepare-python --apply
```

可使用工具环境中已核验的 uv 托管基础解释器启动更新器。后续日常业务使用目标 ROOT 的项目 .venv。

工具使用 SQLite Backup API 保留恢复副本，暂存匹配程序及组件，记录原配置和恢复日志，并校验保护文件和业务哈希。原发布门禁保持其值，已有显式 publisher 路径可更新为同身份新 helper。程序更新流程本身不调用 refresh、云端发布、收件或回执。

覆盖升级需要同时核对实际安装下限。Android 另取同版、原身份、原签名的 APK 覆盖安装。设备不可用时保留待执行项。

## 5. 更新后实际重读与验收

1. 读取实际 releaseDocs 中的本文件、[版本衔接指引](版本衔接指引.md)和适用的变更文档。
2. Preview 重读实际同步到使用根的 Skill 入口及本次所需 references。Personal 读取本人维护的 Skill，并按目标契约核对兼容性。
3. 核对账本业务哈希、保护文件、绑定、helpers 及实际 App 打开情况。
4. 按累计衔接指引检查尚未完成事项。历史收入复核属于业务审核，先按授权与所选期间处理。
5. 在本人 local 中记录目标版本/提交、已完成和待定事项及证据位置，分开报告程序、文档、业务衔接、云端和设备。

相同版本可重试补齐适用的 Skill/管理状态，清单和组件仍须与已采用版本一致。同版内容发生变化或来源不明时保留现场。聊天缓存须通过实际重新读取刷新。

## Skill 冲突如何处理

### Preview 随版管理

更新器管理 `.agents/skills/account-maintenance/SKILL.md` 及必要 references，另存内容基线。本人长期规则放在 local/个人规则.md，其他 Skill 与所有者文档按原范围保护。

| 状态 | 含义 |
| --- | --- |
| synchronized | 字节匹配已记录来源，仍须实际读取 |
| pending | 预检计划同步目标 Skill |
| modified | 当前字节偏离已记录基线，先保留与核查 |
| untracked | 尚无受管来源基线 |
| unsupported | 此旧包未提供受支持的随版 Skill |
| owner-managed | 个人 Skill 由本人维护，按下一节处理 |

遇到冲突，先备份本机入口及 references 到本机恢复目录，记录所报文件和已采用版本。比较时区分**当前已安装版本的基线**和**拟升级版本的目标内容**。

1. 已有受管基线时，从可信的已安装版本源码归档恢复当前版本的官方字节，核对后再让更新器同步目标版。直接把目标版复制到旧基线上仍可能被报冲突。
2. 本机差异含私人规则时，先保留原文及出处。已批准内容转入 local/个人规则.md，未确认内容标为候选。核对后恢复当前官方字节，再重跑目标预检。
3. 尚无 Skill 基线时，按工具支持的旧官方来源迁入逻辑核验。原来源、归属或批准依据不清时报告具体缺口。
4. 若已安装的就是目标版本，用该版可信源码恢复缺失/改动文件。预检可能显示 pending，执行并核对状态后才能报告 synchronized。

保留原更新状态和备份，按正式工具检查恢复结果。

### Personal 所有者管理

支持该策略的工具遇到 personal-local 索引 `skillPolicy: local-only` 时不写入个人 Skill，报告 owner-managed。预检/执行报告可能提供 entryPresent，status 输出依工具版本而定，必要时只读核对入口实际存在。

过渡包可能仍携带公开 Skill，策略生效后也按所有者管理。旧更新器兼容和 `--omit-skill` 的准备条件由[开发同步与发布规范](开发同步与发布规范.md)说明。缺个人入口时由本人恢复，公开 Skill 供比对目标契约。

## 失败与中断

| 停点 | 先核对什么 | 如何续接 |
| --- | --- | --- |
| 网络、来源、哈希或平台失败 | 具体请求、固定版本、文件及清单 | 修复该环节，按同一目标重跑 |
| 程序基线冲突 | 实际本地修改与已采用来源 | 备份并处理冲突后预检 |
| Skill 冲突 | 受管基线、个人差异 | 按上文恢复可信来源 |
| Python 依赖准备失败 | 外部 UPY、依赖/网络错误 | 修复环境，继续核验 |
| 安装器失败 | 程序恢复日志、外部安装结果 | 核对实际安装状态后恢复或完成同版更新 |
| pending 或 update.lock | 进程是否仍在、恢复 journal 与切换文件 | 根据日志处理未完成操作 |
| 程序成功、业务衔接未完 | 本机记录与实际审计证据 | 只续接尚未完成事项 |

恢复证据位于 `.runtime/product/recovery/`。工具会尝试恢复程序、helpers 清单和改过的配置，外部安装器可能已部分改变 App，最终状态须实际核对。保留已验证旧组件和有效快照。

业务数据库恢复按[工作说明](工作说明.md#导出备份与恢复候选)创建全新候选，核对后由本人授权切换。程序升级失败后的业务记录继续以当前有效账本为准。
