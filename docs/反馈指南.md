# 反馈问题

先定位失败环节并保留有效账本、快照和恢复记录。Agent 可在本机收集诊断并整理反馈草稿，由本人检查脱敏内容，明确要求提交后再发布 Issue。

## 先确认停在哪一步

| 现象 | 先检查 |
| --- | --- |
| 配置或安装失败 | 绝对项目根、所选发布版、平台、启动器 steps 与退出码 |
| 入账失败 | prepare/import 预检结果及具体来源错误 |
| 已入账但页面没变化 | verify、本地快照、桌面绑定与实际打开的 App |
| 手机没更新 | 电脑云端回读、手机版本、配对及获取状态 |
| 手机仍显示待处理 | 本机入账证据、回执 pending/blocked/receiptErrors |
| 更新中断 | update-status、pending、update.lock 与恢复 journal |

日常失败续接见[记账 Skill 恢复说明](../.agents/skills/account-maintenance/references/recovery.md)，升级失败见[更新与恢复](更新与恢复.md)。诊断按所选命令的实际影响执行。

## 反馈应包含什么

- 系统、CPU 架构、产品/安装版本、安装身份及公开版本来源。
- 在哪个页面或命令遇到问题，具体复现步骤。
- 预期结果、实际结果、首次出现时间及安全错误码。
- 已执行的核对与结果，包括哪些尚未执行。
- 可复现时使用最小虚构样本，注明真实环境与合成演练的区别。

使用[问题模板](../.github/ISSUE_TEMPLATE/bug_report.yml)或[建议模板](../.github/ISSUE_TEMPLATE/feature_request.yml)。提交前让本人看到具体草稿。

## 哪些信息留在本机

真实 SQLite、原始账单、完整审核、local、PROJECT_MEMORY、整份 .runtime、安全存储、密码/令牌、配对二维码、完整订单/账号均留在本机。截图遮盖姓名、交易、二维码和路径用户名，日志先检查是否含私人内容。

共享反馈只保留定位问题需要的脱敏结论、错误码、时间及必要修订信息。提交问题后，改账、安装、云端发布与恢复操作继续按各自实际授权执行。
