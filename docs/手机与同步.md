# 手机与同步

本功能供已完成电脑本地使用的人按需启用，当前支持 Android arm64。继续使用已有账本、规则和预算。未选择本功能时，本地记账与查看照常完成。

本页的 PY 为本人项目 Python，ROOT 为本人绝对项目目录，命令工作目录为 ROOT。既有安装升级先读[更新与恢复](更新与恢复.md)，数据处理范围见[同步与隐私](同步与隐私.md)。

## 开始前确认

| 项目 | 需要确认什么 |
| --- | --- |
| 本地账本 | 电脑 verify 通过，App 能查看有效本地快照 |
| 版本与身份 | 电脑、三件 helpers、手机使用匹配发布版与同一安装身份 |
| 设备与账号 | Android arm64、本人的坚果云账号和两端各自应用密码 |
| 同步授权 | 本人知道将同步展示明细与汇总，明确选择启用 |
| 已有状态 | 有身份、配对、凭据或门禁时按实际状态续接 |

## 1. 安装 Android App

核对电脑实际安装版本和 profile，从[发布页](https://github.com/Milozpace/Account-Preview/releases)取得同版 Android arm64 ZIP，校验 SHA256SUMS 与包内清单，解压 install 下的已签名 APK。历史 preview.1 提供独立 APK，按其发布说明处理。

本人可以手机直接下载，或由 Agent 在电脑下载校验后通过本人选择的方式传到手机。安装时按系统提示处理本来源安装授权，已有 App 沿用原身份和签名覆盖安装。

公开用户使用 preview，原个人安装继续 personal 的获准本地交付。实际安装和启动需在设备上核对，设备不可用则标待执行。

## 2. 核对或建立电脑同步身份

SQLite 初始化与同步安全身份分开。匹配组件已就绪、当前本地账本及快照有效后，按本人扩展授权执行。

```text
PY bootstrap.py --apply --expected-root ROOT --initialize-identity
```

工具先读取原生状态，仅在尚无身份时初始化，重复执行保留已有身份。这一步不打开发布门禁。状态异常时先核对现场。

macOS 的钥匙串授权由本人在系统窗口核对对应应用/工具后处理。密码、系统授权和配对材料由本人操作。

## 3. 两端设置连接并扫码

电脑进入“应用设置 → 手机与同步”。手机未配对时，总览的“连接电脑账本”引导“扫码配对 → 同步连接 → 获取账单”。按当前缺少的步骤继续。

在电脑的设备配对区域显示二维码，由本人用手机扫描。二维码绑定账本安全身份，桌面应用密码仍需在手机单独填写。

两端分别在原生“同步连接”界面填写本人坚果云账号及各自应用密码。

| 字段 | 内容 |
| --- | --- |
| WebDAV 地址 | App 内置 `https://dav.jianguoyun.com/dav/` |
| 账号 | 本人的坚果云账号邮箱 |
| 应用密码 | 为当前设备生成的应用密码 |

应用密码的生成按[坚果云官方说明](https://help.jianguoyun.com/?p=2064)，WebDAV 口径见[官方示例](https://help.jianguoyun.com/?p=5677)。页面位置可能变化，按官网实际提示操作。账号注册、登录、验证码和密码由本人处理。

尚未取得账本快照时，查询/导出入口按页面状态开放。已缓存账本可离线查看。连接失败时在同步页查看具体原因并重试已有步骤。

0.4.0 起，候选凭据先通过只读云端请求验证，再保存到安全存储，失败保留旧凭据。“已配置”只说明本机保存过配置，不保证当前能访问云端。验证不会建立目录或发布账单。

同步提示按“待完成、需要留意、需要处理”说明原因、缓存影响和下一步，详情保留阶段与 HTTP 状态。401、403 和 409 分别核对认证、权限或路径，不能统一归为密码错误。空云端需要检查电脑首次发布与两端账号。

新旧快照契约、损坏和解密失败分别处理，保留有效缓存。已经认证的新契约快照要求手机覆盖更新；旧契约要求电脑更新并重新发布。旧 App 首次升级后才具备这些提示，不能依赖旧版错误文案判断；不卸载或重新配对。接口与完整问题类型见[同步问题提示](同步问题提示.md)。

## 4. 授权开启并确认首次同步

先向本人说明当前快照的实际范围，可能包含已有真实交易的展示明细和汇总。取得本次同步授权后继续。

```text
PY bootstrap.py --apply --expected-root ROOT --enable-publish
PY scripts/account.py --root ROOT refresh --apply
```

第一条开启原生主门禁和本地 publish.json 门禁，本身不上传。第二条生成展示，并沿门禁尝试发布。读取实际发布及云端回读结果，再由本人在手机获取并核对月份与版本。

开启后，后续导入/刷新可能自动发布，Agent 应在本机状态中记录本人的授权范围。doctor 的 unverified 仅表示未验证。合成诊断通道结果与真实账本发布回读分别核对。

### 云端目录与归属

| 安装身份 | 展示快照 | 原账单收件箱 | 合成诊断 |
| --- | --- | --- | --- |
| preview，com.account.preview | Account-Preview/ledger | Account-Preview/inbox/身份摘要 | Account-Preview/probe |
| personal，com.account.probe | Account/ledger | Account/inbox/身份摘要 | Account/probe |

preview.3 起按构建身份选择目录，personal 保持原路径。两种身份可以共用本人云账号；同一身份的多个独立账本应使用各自云账号和目录归属。

旧 preview.2 及以前的云文件仍保留在旧 Account 目录。新版凭据和配对可沿用，新根须实际发布回读后确认。旧根的发布确认与恢复证据只说明当时的旧目录结果。

目标目录无法认证时先核对 profile、配对和云账号。保留有效文件与缓存，任何云端归档/清理由本人根据实际归属安排。

## 5. 手机投递账单，由电脑审核入账

在“我的 → 上传原始账单”选择文件，上传原件的加密副本至独立收件箱。rc.1 支持多文件选择，按各文件实际结果报告。电脑需运行 Agent 的收件与记账流程。

| 环节 | 谁执行 | 完成依据 |
| --- | --- | --- |
| 上传 | 手机 | 文件上传结果 |
| 收取归档 | 电脑 Agent | 收件工具核验及 sra 归档 |
| 审核入账 | 电脑 Agent | 审核批次、SQLite 提交与 verify |
| 回执 | 电脑核验后发送，手机读取 | 认证回执与对应入账证据 |
| 展示更新 | 电脑发布，手机获取 | 云端回读和手机实际页面 |

Agent 从[记账 Skill](../.agents/skills/account-maintenance/SKILL.md)执行。手机上传成功后，用户可说“请收取我刚从手机上传的账单并记账”。已授权收件时先 fetch，再从本机 status 取得本批归档路径。手机上传不会直接写 SQLite。

## 停点与完成标准

| 停点 | 续接 |
| --- | --- |
| 未配对或连接未完成 | 继续页面当前步骤 |
| 同步认证失败 | 核对身份、凭据状态与云账号，保留有效缓存 |
| 电脑已发布、手机未更新 | 核对同版安装、手机获取结果及实际页面 |
| 上传成功、尚未入账 | 让电脑 Agent 按收件记账流程处理 |
| 已入账、回执失败 | 按 Skill 的恢复说明核验并重试回执 |

分别报告安装、身份、凭据配置、配对、双门禁、云端回读和手机显示。选用账单投递时再补充上传/收取/入账/回执各环节结果。每项以实际证据确认，未执行项明确保留。
