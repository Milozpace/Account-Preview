# 手机与同步（可选）

先完成[电脑本地 mini 体验](开始使用.md)：本人能通过 Agent 记账，并在电脑 App 查看。没有手机、没有坚果云账号、未配对都不影响本地使用。只有本人选择手机查看或上传账单时，才继续本页；当前手机端支持 Android arm64。

沿用现有账本、个人规则和桌面绑定，不重新 init SQLite、不重新导入已入账文件，也不重置预算。预算尚未制定时仍按观察阶段解释。下文 `PY`、`ROOT` 含义同开始使用。

## 1. 安装 Android App

先确认电脑实际采用的已发布版本与 profile，不使用 main 候选版本猜测。由已配置项目的更新状态、helpers 清单和安装信息交叉核对，再从[发布页](https://github.com/Milozpace/Account-Preview/releases)取得同版 Android 包。0.4.0 首版提供独立 APK；0.4.1 起按 release-manifest.json 的 profile/android-arm64 取得 ZIP，校验外层及包内清单，再解出 install/ 下的已签名 APK。普通朋友为 preview，原个人版为 personal，不混装，不把 CI unsigned 包当可安装交付。

手机可从公开发布页直接下载，无需 GitHub 登录，也可由电脑下载并按清单和 SHA256SUMS 校验后，经 USB 或本人选择的文件传输方式交到手机。点开 APK，按 Android 系统提示完成本来源安装授权；已有 App 保留原签名覆盖，不卸载删除数据。Agent 先确认 arm64 和安装身份，再引导本人操作；未连接设备时不能报告已安装或升级。以后版本更新继续按同一发布索引选择，不永久固定首版链接。

## 2. 建立同步安全身份

SQLite 初始化不创建 App 安全身份。完成组件安装、现有本地账本核验与本机快照后，执行：

```text
PY bootstrap.py --apply --expected-root ROOT --initialize-identity
```

该步骤使用已安装的匹配 helper，先读取原生状态，仅在尚无身份时初始化。重复执行保持已有身份；不要反复直接调用原生 `--init`。此步骤不打开发布门禁、不上传。若身份状态异常，保留现场并排查，不能重建身份来跳过错误。

macOS 若弹出钥匙串访问授权，由本人核对 Account Preview 或当前辅助工具，并在系统窗口处理本机授权。Agent 不接收本机登录密码，也不替用户绕过钥匙串授权。

## 3. 本人设置凭据并扫码

没有坚果云账号时，先在[坚果云官网](https://www.jianguoyun.com/)由本人注册并完成验证；已有账号直接登录。Agent 可以打开官网、说明步骤，账号密码与验证码由本人操作。

按[坚果云官方应用密码说明](https://help.jianguoyun.com/?p=2064)，网页右上角账户名 → 账户信息 → 安全选项 → 第三方应用管理 → 添加应用密码。分别创建便于辨认的 `Account Preview 电脑` 与 `Account Preview 手机`；手机坚果云客户端也可在设置 → 第三方应用管理中创建。

电脑从“应用设置 → 一般 → 手机与同步”进入既有同步页面（返回可回到一般设置），手机从“我的 → 同步连接”进入。在两端的“同步连接”表单填写账号与应用密码。此入口与“同步展示”的刷新动作不同。坚果云 WebDAV 地址已由 App 内置，无需另填：

| 字段 | 填写内容 |
|---|---|
| WebDAV 地址（App 内置） | `https://dav.jianguoyun.com/dav/` |
| 账号 | 本人的坚果云账号邮箱 |
| 应用密码 | 刚为当前设备生成的应用密码 |

地址和账号口径见[坚果云官方 WebDAV 示例](https://help.jianguoyun.com/?p=5677)。应用密码不同于网站登录密码；Agent 不代读密码或截图。需要重新生成时先明确对应设备，更新该设备的设置，不重建账本身份。页面位置可能变化时以官网现有说明为准。

你分别在**电脑和手机** App 原生设置中填写坚果云 WebDAV 信息，每台设备使用各自的应用密码；桌面的密码不会通过配对二维码传到手机。Agent 不接收、读取或记录密码，配对二维码/截图不进入聊天。

身份就绪后，由你在电脑显示配对二维码，手机扫码。每位用户建立独立身份，不复用他人密钥或配对。确认两端设置与配对完成，再进入首次同步。

## 4. 获准后开启同步

先说明：首次同步会加密上传当前账本的展示快照，可能已包含真实交易的展示明细和汇总；它不是整份 SQLite，也不自动上传电脑原始 CSV/XLSX。本人已授权本次同步时连续执行，不重复确认。

```text
PY bootstrap.py --apply --expected-root ROOT --enable-publish
PY scripts/account.py --root ROOT refresh --apply
```

第一条幂等开启原生主门禁和 `.runtime/ledger/publish.json` 的本地门禁，本身不上传；第二条生成并发布当前快照。必须检查实际加密上传和云端回读，再由本人在手机刷新核对。不能把本机生成文件当作云端或手机验证完成。

开启后，后续导入/刷新可能按门禁自动发布，Agent 应说明这一点。认证或发布失败时保留本机账本与有效快照，不重建身份或重新配对掩盖错误。

## 5. 手机原账单投递与验收

本人可以在手机“我的 → 上传原始账单”选择文件。该操作会把原件的加密副本送入坚果云独立收件箱；电脑 Agent 校验、归档至 `sra/`、审核入账并核验后才回传认证回执。云端保留的加密对象不等于文件从未离开设备，详见[同步与隐私](同步与隐私.md)。Android 不直接写 SQLite。

分别报告安装、凭据、身份、扫码、双门禁、云端回读、手机查看，以及选用上传功能时的投递/收取/入账/回执。缺设备标未验收；没有选择本扩展时报告“手机与同步未启用（可选）”，不列为本地配置失败。
