# 日常审核契约

prepare 负责原件解析、身份及去重候选；Agent 审定派生字段。以当前工具预检为准，不为通过校验改原始事实。

| 位置 | 要求 |
|---|---|
| `source_files` | 保留本批归档绝对路径和 SHA-256；重新 prepare 采用新输出，不手编来源证据。 |
| 原始事实/身份 | 保留平台、时间、对方、说明、原始类型/分类、方向、金额、方式、状态、订单及 ID/来源行；原始金额不因退款/分摊改写。 |
| `records` 每行 | 明确填写 `最终财务事件`、`统计口径`、`计入消费金额`、`主分类`、`资金池`、`语义说明` 六项，不用默认候选代替实际审核。 |
| `reviewed_by` / `reviewed_at` | 实际 Agent/审定者标识和本次带时区 ISO 8601 时间，不借旧审核者。 |
| `reason` / `confirmation_source` | 真实理由、原始证据、批准规则 ID 或本次用户回复出处；Agent 推断不能写成用户确认。 |
| `conflicts` | 同身份原始事实不一致是真冲突，定位解决后导入，不删标志冒充重复。 |
| `review_required` | 实际审核后可设 false；单改标志不是审定。 |

## 口径与取值

- 非零 `计入消费金额`（含负数退款）：`统计口径` 为 `PERSONAL`、`PROJECT` 或 `STRUCTURAL`；前两者参与本人净消费和四池，后者单独统计。
- 确认不计消费：净额确定为 `0.00`，规范口径 `EXCLUDED`，写真实事件和排除理由。收入、资金搬移仍保留账本记录，消费者快照只展示消费口径。旧 Excel 中文口径、“不计入”等旧别名不作当前输入规范。
- 经审核确认的实际收入：`统计口径=INCOME`。金额就是实际到账的 `原始金额`，`计入消费金额` 必须为 `0.00`，`资金池` 必须留空，`主分类` 必填（如工资薪酬、经营收入、稿费等自由文本）。收入独立于消费、四池与滚存统计；互转、报销返还、代收代付、借款不是收入，按事件走 `EXCLUDED` 或对应口径，不能只按金额正负分类。收入冲回不是常规功能：错误入账、工资追回等用有证据、关联原收入行（`关联记录ID`、事件 `income_reversal`）的负向收入记录净额化，避免重复冲减；收入行携带 `退款调整` 会被校验拒绝。
- `UNKNOWN` 不是给未知金额填零的通道。金额/净额/事件未审定的行留候选，不导入猜测金额；真实消费仅用途未定时仍用实际 PERSONAL/PROJECT 金额，主分类/池可 Unknown/待归类并解释。
- `最终财务事件` 为可解释文本，如 `purchase`、`refund`、`transfer`、`reimbursement`，不能代替合法统计口径。
- `资金池` 仅四个固定池、空值或 `待归类`；Unknown 不是合法池名。安全积累是计算结果，不是第五池。待分池在 `资金池判定` 或 `语义说明` 写具体缺少哪项用途证据。
- 主分类为用户能理解的自由文本，未知可 Unknown，不编造置信度。退款/报销/分摊先关联核对净额，不凭同额自动关联。

`classificationReview` 仅覆盖本批实际新增/修改的非零本人/项目消费，不是全库待办。核对覆盖、净额、待定原因、警告及 `reviewComplete`；仅全部消费均有主分类与分池时为 true。有依据的少量待定可入账，但该标志仍为 false，报告分类/分池尚有待确认，不能称全部完成。不能把未审核/缺解释的整批待定报完成，也不为清警告猜用途。重复预检无变更时计数为零不表示全库已分类。

## 部分暂缓

把事件/净额未定的候选 ID 和具体问题存本机待办；已确定部分可独立审核入账。保留原 prepare 来源和生成字段，不改原件、不手写遗漏行。之后用原归档文件重新 prepare，程序去除已提交记录，审核剩余候选并采用最新生成事实。原件尚有未入账行时不宣称整份文件完成，手机回执 pending 可能正是此范围未完成。

## 已入账纠正

先用正式只读命令，按本次确认的月份/关键词有限定位记录：

```text
PY scripts/account.py --root ROOT find-records --month YYYY-MM --query 关键词 --limit 20
```

至少提供月份或关键词之一，`--limit` 为 1–100。输出 `matchedRecords`、`truncated` 和有限的 `records`；只含记录 ID、时间、对方、商品/说明、分类、池、口径和计入消费金额，不含订单号。若截断，缩小月份/关键词再查，不改为遍历全库或扫描旧原件。

沿用现有记录 ID，不重建原始行。审核 JSON 使用 `records: []` 和明确 `updates`，顶层保留实际审定信息；每项有 `记录ID`、`changes`、`reason`、`confirmation_source`。理由和出处引用本次实际确认，仅允许工具白名单中的派生字段；原始前 12 字段、`记录ID`、`来源文件`、`来源行` 不可更新，也不能在新增的同批 updates 中重写来源定位。

用户明确纠正某笔日常通勤用途时，仅更新该笔分类、池等相关派生字段，具体 ID 取现有账本，不能手造。预检无冲突且修改已获授权就 apply、verify、再预检幂等；单笔纠正不改长期规则或其他历史记录。
