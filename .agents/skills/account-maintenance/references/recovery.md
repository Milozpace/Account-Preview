# 日常记账失败与续接

按已经发生的事实续接，保留账本、审核文件、归档和有效快照，不以重建、删锁或重导掩盖失败。

| 状态 | 下一步 |
|---|---|
| 来源异常/账本缺失 | 保留现场核对本人根和 `data/source.json`；缺个人文档不是重新初始化理由。 |
| prepare 解析/哈希失败 | 核对本批原归档和具体错误，不扫所有旧原件或改原件绕校验。 |
| 来源/原始字段不符、冲突 | 按具体 ID/路径定位，保留生成证据，修来源或重新 prepare，不把冲突称为重复。 |
| import 预检不通过 | 按准确错误补审核派生字段，未知金额不补零，审核者不借旧名。 |
| apply 事务失败 | 工具回滚；核对当前修订和记录状态，修错重试，不直接 SQL。 |
| 已提交、快照失败 | 先 verify 成功账本，修复展示后按原授权刷新；不重复写入或回滚成功交易。 |
| 回执 `pending` | 查看 `unimported-records`，属来源仍有未入账候选的待处理信息，不等于已完成部分写入失败；原归档 reprepare。 |
| 回执 `blocked` | `source-conflict`/`source-changed`/`source-missing`/`source-redirected`/`source-empty`/`missing-provenance`/`proof-error` 为阻塞，`ok=false`；报告具体原因，不清标志或误报成功。 |
| 已入账，仅回执上传失败 | `receiptErrors` 与上面待处理/阻塞分开；`inbox-receipts --apply` 核验本机及账本证据后重试，不重导记录。 |
| 同审核文件重复预检 | 应新增/更新零、修订与业务哈希不变；非零或冲突查具体记录。 |

import/refresh 可能沿原双门禁自动发布，核对授权；账本、快照、云端回读、回执和设备显示分报。未选同步时不为记账建身份、重新配对或配凭据。

需要数据库恢复时，用 Backup API 副本生成全新候选，核验完整性、来源、修订、净额及后续记录，由本人明确授权替换来源；不直接覆盖当前库。程序更新/更新恢复仍按项目更新文档，日常记账不负责更新。
