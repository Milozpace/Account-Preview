# Account Preview

让自己的本地 Agent 帮你记账，再用 Windows / macOS App 查看。首轮是一个 **mini 体验：先整理一个月的账单，看懂支出，再逐步了解自己的分类和管理需要**。日常记账必须使用仓库随版提供的[核心 Skill](.agents/skills/account-maintenance/SKILL.md)，无需另行全局安装 Skill、完整开发工具链或模型 API 配置。

默认先完成电脑本地体验；Android 手机查看、账单投递和坚果云同步是后续[可选扩展](docs/手机与同步.md)。不需要一开始注册云端账号、安装手机 App 或完成配对。

每人建立独立账本与个人规则，不继承作者的历史数据、预算和消费约束。第一轮不要求事先设计预算或完整分类体系；Agent 首次导入就按真实用途完成主分类和四池分配，实际歧义才说明并待确认。分池不依赖预算，之后再用简短访谈调整个人偏好。新账本预算默认全零，处于观察阶段，显示“未设预算”；实际消费、日历、分类和分池照常可看，观察期不产生超支、滚存欠账或安全积累。需要额度时进入“设置 → 四池预算”，首次可从导入月生效。新旧账本的计算边界见[开始使用](docs/开始使用.md)。完整个性化支出管理仍需继续迭代。

**第一次使用：[开始使用](docs/开始使用.md)。** 从[发布页](https://github.com/Milozpace/Account-Preview/releases)选择已发布试用版，电脑由 Agent 选择匹配架构的 ZIP；选择手机扩展时再取得同版 Android 包。首版 [0.4.0-preview.1](https://github.com/Milozpace/Account-Preview/releases/tag/v0.4.0-preview.1)保留作历史下载入口，不代表永远是最新版本。仓库已公开，读取源码和下载发布包无需邀请或 GitHub 登录。

首次配置先读默认分支的最新指引，再使用所选已发布标签的同版源码与安装包。启动器的 --expected-root、显式改绑等参数以所选标签的同版文档为准，不把新命令直接套在旧代码上。[构建验证记录](docs/本轮验证记录.md)用于区分构建/合成演练与实际设备验收。

**版本来源：** 源码版本见 `release.json`；是否已发布、哪些版本可下载以发布页为准，不从默认分支推断。首次安装须取同一已发布标签的源码与安装包。`0.4.0-preview.2` 起支持从本人账本起点持续保留月份、可选预算和分步手机连接；`0.4.0-preview.3` 修复 Android 扫码、分离两种安装身份的云端目录，并优化电脑设置与主动额度编辑。旧 `0.4.0-preview.1` 仅展示本月和上月。安装包内部版本独立递增，不用于判断产品是否已正式发布。

`0.4.0-preview.4` 集中优化 Agent 日常记账、四池审核、来源一致性和回执诊断，并支持更新配套 Skill；App 界面和原生功能保持。具体可下载版本仍以发布页为准。

## 开发、发布与更新

从 `0.4.0-preview.5` 起停止支持 Intel Mac，macOS 仅提供 Apple Silicon 包；历史版本资产保留。

已有用户更新包括：取得已发布固定版本 → 覆盖程序与配套 App／helpers → 重读同版文档和官方 Skill → 按[累计版本衔接指引](docs/版本衔接指引.md)完成适用事项。先读远端最新更新入口，不在使用目录直接 git pull；程序已更新不能替代历史收入复核。通用文档从更新结果 `releaseDocs` 读取，本人的规则和确认继续保留。

开发者先读[开发状态与交接](docs/开发状态与交接.md)、[版本与分支管理](docs/版本与分支管理.md)和[架构与部署边界](docs/架构与部署边界.md)。main 保留经验证交付，dev 集成下一轮功能，短期 feature/fix 分支合回 dev，旧版 hotfix 修复回流。版本号、渠道、安装身份和分支分别管理：同一源码的 personal/preview 共用产品版本，个人可先用新候选；普通提交用 SHA，实际交付才编号，tag 固定发布。当前仍处预览阶段，不因分支命名就宣称已有稳定版。

共享功能以后统一在本仓库开发，个人 Account 只保留本人数据、规则和配置并消费发布版本。提交、CI 候选和正式 Release 是三个不同阶段；**新版本须维护者明确批准，发布说明先由 Agent 起草，再由维护者润色或确认最终稿**。工具不会自动发布或改变仓库可见性。

已有用户对 Agent 说：

```text
帮我把 Account 更新到最新已发布的试用版。先读远端最新的 docs/更新与恢复.md，检查本机采用的安装身份和源码修改，再预检升级。覆盖更新后，实际重读 releaseDocs 中的同版更新文档、累计版本衔接指引，以及已同步的官方记账 Skill 和相关 references，按该版指引完成适用的衔接与核验。收入复核默认最近三个月、短历史全部；历史超过三个月先让我选范围，真实分类歧义再问。保留我的账本、原件、个人规则、预算、凭据、配对和同步门禁；不要把开发分支当已发布版，不重新初始化或配对，不扩大云端授权。分别报告程序、文档、收入复核及设备状态。
```

Agent 入口见[更新与恢复](docs/更新与恢复.md)；维护者见[开发同步与发布规范](docs/开发同步与发布规范.md)。现有个人版使用 `personal` 身份，朋友默认 `preview`，同一源码分别构建，更新时不得混装。旧 `0.4.0-preview.1` 没有新版更新清单，工具会停止并说明原因，不假装已升级。

## 发给 Agent

```text
请帮我配置这个 Account 公有仓库：https://github.com/Milozpace/Account-Preview 。
直接读取公开仓库和发布页，不要求 GitHub 邀请、账号或登录；遇到实际网络问题说明原因，不在聊天中接收密码或令牌。
读 README.md、AGENTS.md、docs/开始使用.md 和 docs/工作说明.md，默认先完成电脑本地 mini 体验。
让我选定长期保留的普通目录，核对完整绝对路径与源码来源；新启动器执行时传 --expected-root。准备项目专用 Python、安装并绑定同一已发布版本的电脑版 App。
先问我想整理哪个近期月份、有哪些本地账单文件。优先完整的上月；不要一开始要求我规划四池额度或设计完整分类体系。
新空库按文档用默认全零预算与零滚存初始化，记录“预算未制定”，不把零值当作我的支出上限。仅新初始化账本采用观察模式；保留已有账本、参数和计算方式，不根据旧零值猜意图或自动迁移。
首批及以后日常记账必须读取 .agents/skills/account-maintenance/SKILL.md，由它负责本地/手机来源、审核分类分池、入账核验与事后纠正。少量小额用途不明可据实暂留待归类，记完集中说明；用户补充后通过审计 updates 修正。不要在配置提示中另外维护一套记账流程。
看完一月记录后，再用两三个简短问题了解我想关注哪块支出、哪些分类不合适；允许我暂不制定预算。保存长期规则前取得明确确认。
手机、坚果云、同步身份、应用密码和配对先不配置；我选择扩展后再按 docs/手机与同步.md 引导。
报告本地已完成、主分类及分池各自的已分配/待确认笔数与金额、待定原因，以及未启用的可选功能。个人账本和资料不进共享仓库；后续若授权开发，验证后主动提交相关代码。
```

日常直接使用[核心记账 Skill](.agents/skills/account-maintenance/SKILL.md)；目录职责见[工作说明](docs/工作说明.md)，简短访谈和规则积累见[规则与学习](docs/规则与学习.md)，开发与反馈见[开发指南](docs/开发指南.md)和[反馈指南](docs/反馈指南.md)。

本轮实测问题与修复范围见[配置流程反馈处理记录](docs/配置流程验收.md)，其中区分源码修复、文档约定与尚待发版的安装包。

隐私小注：账单和账本默认在本机，供本人及本人授权的 Agent 处理，不提交共享仓库。若 Agent 使用云端模型，它读取的内容可能按其设置发送给模型服务；选用手机上传后也会有坚果云加密中转，边界见[同步与隐私](docs/同步与隐私.md)。
