# Account Preview

让自己的本地 Agent 帮你记账，再用 Windows / macOS App 查看。首轮是一个 **mini 体验：先整理一个月的账单，看懂支出，再逐步了解自己的分类和管理需要**。普通使用无需安装完整开发工具链，不要求专属 Skill，也没有模型 API 配置项。

默认先完成电脑本地体验；Android 手机查看、账单投递和坚果云同步是后续[可选扩展](docs/手机与同步.md)。不需要一开始注册云端账号、安装手机 App 或完成配对。

每人建立独立账本与个人规则，不继承作者的历史数据、预算和消费约束。第一轮不要求事先设计预算或完整分类体系；Agent 在看到实际记录后做简短访谈，逐步调整。现有四池预算界面仍保留，预算未制定时的技术占位与显示限制见[开始使用](docs/开始使用.md)。完整个性化支出管理仍需继续迭代。

**第一次使用：[开始使用](docs/开始使用.md)。** 从[发布页](https://github.com/Milozpace/Account-Preview/releases)选择已发布试用版，电脑由 Agent 选择匹配架构的 ZIP；选择手机扩展时再取得同版 Android 包。首版 [0.4.0-preview.1](https://github.com/Milozpace/Account-Preview/releases/tag/v0.4.0-preview.1)保留作历史下载入口，不代表永远是最新版本。仓库已公开，读取源码和下载发布包无需邀请或 GitHub 登录。

首次配置先读默认分支的最新指引，再使用所选已发布标签的同版源码与安装包。新启动器的 --expected-root、显式改绑等参数属于下一候选版，旧标签应按该版文档执行，不把新命令直接套在旧代码上。[构建验证记录](docs/本轮验证记录.md)用于区分构建/合成演练与实际设备验收。

**版本来源：** 源码版本见 `release.json`；是否已发布、哪些版本可下载以发布页为准，不从默认分支推断。2026-11-01 本轮记录：`0.4.1-preview.1` 尚为候选，已发布首版为 `0.4.0-preview.1`，后续发布不由这条历史记录决定。首次安装须取同一已发布标签的源码与安装包，不把开发分支源码搭配旧安装包。0.4.1 的新能力支持从本人账本起点持续保留月份；0.4.0 仍只有本月和上月。

## 开发、发布与更新

共享功能以后统一在本仓库开发，个人 Account 只保留本人数据、规则和配置并消费发布版本。提交、CI 候选和正式 Release 是三个不同阶段；**新版本须维护者明确批准，发布说明由维护者本人撰写**。工具不会自动发布或改变仓库可见性。

已有用户对 Agent 说：

```text
帮我把 Account 更新到最新已发布的试用版。先读 docs/更新与恢复.md，检查本机采用的安装身份和源码修改，再预检升级。保留我的账本、原件、个人规则、预算、凭据、配对和同步门禁；不要把开发分支当已发布版，不重新初始化或配对。
```

Agent 入口见[更新与恢复](docs/更新与恢复.md)；维护者见[开发同步与发布规范](docs/开发同步与发布规范.md)。现有个人版使用 `personal` 身份，朋友默认 `preview`，同一源码分别构建，更新时不得混装。旧 `0.4.0-preview.1` 没有新版更新清单，工具会停止并说明原因，不假装已升级。

## 发给 Agent

```text
请帮我配置这个 Account 公有仓库：https://github.com/Milozpace/Account-Preview 。
直接读取公开仓库和发布页，不要求 GitHub 邀请、账号或登录；遇到实际网络问题说明原因，不在聊天中接收密码或令牌。
读 README.md、AGENTS.md、docs/开始使用.md 和 docs/工作说明.md，默认先完成电脑本地 mini 体验。
让我选定长期保留的普通目录，核对完整绝对路径与源码来源；新启动器执行时传 --expected-root。准备项目专用 Python、安装并绑定同一已发布版本的电脑版 App。
先问我想整理哪个近期月份、有哪些本地账单文件。优先完整的上月；不要一开始要求我规划四池额度或设计完整分类体系。
新空库按文档使用全零技术占位并记录“预算未制定”，初始滚存零；已有账本和参数保留。不要将占位值理解成我的支出上限，暂不依据预算区判断超支。
把我选择并授权的账单复制到选定项目的 sra/，核对哈希且不覆盖旧件、不删除来源。然后先审核净额和必要的退款/转账关系，做简单、可解释的分类，核验后在电脑 App 查看。用途或分池不明确时保留待归类，不强套作者的分类与资金池。
看完一月记录后，再用两三个简短问题了解我想关注哪块支出、哪些分类不合适；允许我暂不制定预算。保存长期规则前取得明确确认。
手机、坚果云、同步身份、应用密码和配对先不配置；我选择扩展后再按 docs/手机与同步.md 引导。
报告本地已完成、待确认与未启用的可选功能。个人账本和资料不进共享仓库；后续若授权开发，验证后主动提交相关代码。
```

日常见[工作说明](docs/工作说明.md)，简短访谈和规则积累见[规则与学习](docs/规则与学习.md)，开发与反馈见[开发指南](docs/开发指南.md)和[反馈指南](docs/反馈指南.md)。

本轮实测问题与修复范围见[配置流程反馈处理记录](docs/配置流程验收.md)，其中区分源码修复、文档约定与尚待发版的安装包。

隐私小注：账单和账本默认在本机，供本人及本人授权的 Agent 处理，不提交共享仓库。若 Agent 使用云端模型，它读取的内容可能按其设置发送给模型服务；选用手机上传后也会有坚果云加密中转，边界见[同步与隐私](docs/同步与隐私.md)。
